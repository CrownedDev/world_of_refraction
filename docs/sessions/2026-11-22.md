## B-573 click fix: the play tool could not click a button (`fix/B-573-agent-click-capture`, for the brain to merge)
- **Seen by the brain in PIE:** a click hovered a button and drew it pressed, but the button never fired (battle menu rows, Status, the party panel's Close). The Gate screen worked because it acts on the press itself.
- **Cause:** a button only clicks on release if it still holds the pointer from the press, and Unreal refuses that hold while the editor is not the app in front. The agent always plays with the editor in the background.
- **Fix:** the hold switches on Unreal's own setting for handling input in the background, and puts it back on release. The pointer held is the agent's; the real mouse is still never moved or captured, and no window is brought to the front. Editor module only, no game code.
- **How it was checked:** a new test in `WoR.AgentPlay.Hold` failed before the fix (hold refused, 0 clicks) and passes after; build; full suite 2417 passed, 0 failed; data validation 13 known, 0 new.
- **Not checked:** nothing in PIE. The test routes the press and release one step below the tool's entry, because a headless run has no shown window to hit-test. Down + Enter doing nothing on the old HUD was not looked into.

## B-578: no input after a fight (`fix/B-578-input-after-fight`, for the brain to merge)
- **Seen by the agent:** back in the trial after a lost or a fled fight, move, Tab and click did nothing until a menu was opened and closed.
- **Cause:** the results screen puts the game in menu-only input, and its Continue button is the level change, so nothing set game input again. Unreal keeps that mode on the game window across a level change (read in engine source: only an input mode ever changes it).
- **Fix, in one place:** a small game-wide service (`UWoRGameInputSubsystem`) gives game input back when a level change starts with menu-only input still on, and leaves every other level change alone. A screen the next level opens on arrival (title, join seat, duplicate prompt) sets its own mode after that, so it is not undone. Every other menu already gave game input back when it closed; the results screen was the only one that could not.
- **New debug command:** `wor.Input.PrintState` says whether the game is ignoring input, so a dead key can be told from a dead game.
- **How it was checked:** the new spec `WoR.Input.LevelChange` (3) failed with the fix switched off and passes with it; build; the full suite; wor-reviewer.
- **Not checked:** nothing in PIE (`docs/PIE/B-578.md`, 10 checks). The spec covers the game window's flags only; keyboard focus and a real level change need PIE. Why this was never seen by hand is not known.
- **Played after that (brain's agent):** QA passed (agent), all 10 checks at `b5d3e0032`: walked after a win, a loss and a flee. Not played by Crown, not with a gamepad, not in co-op.
