## What shipped this branch (chronological)

Five arcs, in order. Each was tagged before its risky step (`pre-*`).

1. **Dynamic effect reshape** — `FSkillEffect` went from {2 fixed conditions + 1 payload + flat scalars} to `{ TArray<FSkillCondition> Conditions[] (per-entry AND/OR via ECondCombine) + TArray<FSkillEffectPayload> Payloads[] }`. Added `EvaluateConditionGroup` (two-predicate fold: Participates + IsMet), stable `EffectID`s, authored `bStackable`/`MaxStacks`/`bFiresOncePerMatch`. Legacy flat fields + `MigrateLegacyToNew` + the parity guard later **deleted**.
   *Tags:* `pre-cluster-b` … `pre-cluster-f3`, `pre-legacy-fields-path-deletion`.

2. **`UEffectDefinition` + reference-only authoring** — effects authored once in a `UEffectDefinition` (`UPrimaryDataAsset` holding `TArray<FSkillEffect> Effects` + `DisplayName` + `Price`), **referenced** from weapons/rings/evolutions/skills via `TArray<TObjectPtr<UEffectDefinition>> ReferencedEffects`. Inline `Effects[]` **deleted** from all owners. Gather via `Get*EffectsGathered()` → `TArray<FGatheredEffect>{ DefID, BundleIndex, Effect }`.
   *Tags:* `pre-effectdef`, `pre-effectdef-c2`, `pre-effectdef-c3`, `pre-refonly-p1`, `pre-refonly-p2`, `pre-refonly-p2c`.

3. **Definition-identity merge** — `EffectID` comes from the `UEffectDefinition`: `PackEffectID(DefID, BundleIndex, PayloadIndex)`. The SAME def referenced by two sources → SAME `EffectID` → merges via `FindEffectByID` (refresh if non-stacking, stack if `bStackable`). Per-Target. Dissolved the equipment actor-window aggregate collision. Caps: ≤10 effects/def, ≤9 payloads/effect, enforced in `UEffectDefinition::IsDataValid`.
   *Tags:* `pre-defid-r1`, `pre-defid-r2`.

4. **Cleanups** — cast physical-DOT now packs by def-identity (was double-packed `WeaponID*10+7`); removed dead window helpers; id-overflow downgraded to a documented NOTE (unreachable); stale `WOR_StartingEffects` reader simplified; cast-`[I]` note resolved.
   *Tag:* `pre-cleanups`.

5. **Defender / conditional trigger system** — effects fire on defense outcomes **at impact**:
   - Triggers appended to `ESkillTrigger`: `OnParry`/`OnPerfectParry`, `OnBlock`/`OnPerfectBlock`, `OnDodge`/`OnPerfectDodge`, `OnTakeDamage`. **Superset** (perfect fires base too). No "miss" trigger. Mapping: `SkillTriggerUtils::DefenseOutcomeToTriggers`.
   - Subject axis: `bTargetSide` (bool) → `ECondSubject { Self, SelfTeam, Target, TargetTeam }` on `FSkillCondition`. Universal "whose state" toggle for all condition types. `ResolveSubjectActors` + team ANY-fold (via `UTurnManager`).
   - Gear-conditional only. Armed per-actor at combat start (`ArmedConditionals`, from `GetActiveConditionalEffectsGathered`). Fired by `OnDefenseResolvedHandler` (subscribes `UDefenseSystem::OnDefenseResolved`). A defense-trigger **guard** keeps threshold-only conditionals out of the impact path. Fired effects resolve per-payload targets via `UActionExecutor::GetEffectTargets` and apply via `ApplyEffect` with def-identity (merge/stacking/fires-once inherited).
   - C3a (arm) `24bd7483`; C3b (subscribe + eval, log-only) `ab7f279b`; C3c (fire) `198a6089`.
   *Tags:* `pre-cond-subject`, `pre-defender-triggers`, `pre-defender-c3`.

## How to test (PIE)

- **Starting effects:** equip gear referencing an always-on bundle; `WOR_StartingEffects` (Exec console) prints PRE per-source + POST applied with a coverage cross-check.
- **Merge:** reference the same `UEffectDefinition` from two equipped items → one merged effect on the actor (not two).
- **Defender trigger:** author a gear bundle "on parry, heal all allies" (`OnParry, Self` → `HealthRestore → Ally (All)`), equip, enter combat, parry. Log shows `[DefenseTrigger] FIRE: …` and allies heal. A pure-threshold conditional is correctly *skipped* on the parry (guard).

## Known limitations (carried)

- Defender-fired effects use `Generic` element (no cast context).
- Attacker perspective is `Subject = Target` only; no separate attacker-side trigger, no accuracy-miss trigger.
- "Cast fires only if target below X%" unsupported at the cast site (needs target threading; target-state eval is the impact path's job).
- `RandomSkill`, `GuaranteedCrit`, `IgnoreDefense`, `DoubleHit`, `Revive` still log-only stubs.
- Per-element immunities enforced only in `UStatusBuildupManager::AddStatusBuildup`.
