## B-503n — A test loadout for the v2 slots

**Branch:** `feature/B-503n-test-loadout-cloud` (from dev `b093b7d02`).

**What changed, in plain words:**
- New console command `wor.Debug.TestLoadout`. It gives the played character a full loadout so R / LB has real sources to step through:
  - up to three weapons, each with a crystal of a different element (the first one in hand);
  - adapters, one with a crystal;
  - an evolution, in a weapon's or adapter's socket, or on its own if no piece takes it.
- Each piece goes in the same way as on the loadout screen, so the class rules decide what fits. The `[TestLoadout]` log line lists what went in and what was refused, and why.
- `wor.Debug.TestLoadout Refractor` (or `Resonator`, `BrokenDarkness`, `Reality`, `Generic`) first makes the pawn that class's test character (`DA_Character_*Lord`). This changes only the pawn, until the next map, not the party.
- `wor.Debug.PrintTestLoadout` repeats the last report.
- It **replaces the active loadout's gear**. The old gear stays owned and can be put back on the loadout screen. The gear given is owned for good, so it reaches the save.

**Decided by default, Crown may change (Q-503n):**
- A variant swaps the pawn only. Fighting-game training modes switch the character without touching the save.
- The evolution goes in a socket, because the v2 rules give an evolution on its own a place only in a free first entry (D-210's own place for it is still a TODO). So a Refractor's evolution is refused.
