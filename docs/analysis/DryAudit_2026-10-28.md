## How it was done

1. **Mechanical scan.** A scratchpad script (`dupscan.py`, plus `fuzz.py`, a fuzzy variant) strips comments and whitespace from all 637 files (~136k lines) and finds runs of 8 or more matching lines. The fuzzy pass also treats as equal: string literals, numbers, and the words Weapon/Ring, Spell/Ability, Primary/Secondary and Buff/Debuff. The results are `scan.txt` and `fuzz.txt` in the scratchpad.
2. **Reading by meaning.** I read code for repeated enum switches, preambles, stat/tier/heal maths, name tables, debug code, save conversion, and weapon/ring, spell/ability and AI/execution pairs.
3. **Context.** I read `DuplicationAudit.md`, Backlog Phase 1, CodebaseReview §5.4 and ArchitectureReview §2. Items those jobs already fixed are not listed again.

**Already fixed (checked, clean):** the per-impact spell resolve and the reflect block (B-032); a single AI damage estimator through the shared preview (B-029, `ActionExecutor.cpp:550-600`); EconomyService preambles (B-025); the authority check (B-027); `ReleaseCombatResources` as the one shared teardown core (B-030); the stone row table (B-021); the Buff−Debuff table (B-020); the gear crystal-op template (`RemoveCrystalFromGear`, B-026); save capture via `SaveItem`/`SaveGearDetail`.

### A1. "Which gear counts" per class: 5 hand-mirrored switches (high drift risk) — M
- **Copies, all in `P/Loadout/LoadoutComponent.cpp`:**
  - `GetActiveStatBonus` :4082
  - `GetActiveResistanceBonus` :4241 (its comment says "Mirrors GetActiveStatBonus's per-class slot resolution exactly")
  - `GetActiveEffects` :4343
  - `GetActiveEffectsGathered` :4434 ("identical per-class gear coverage")
  - `GetActiveConditionalEffectsGathered` :4516
  - a 6th copy in the debug print `SkillEffectManager.cpp:520-592`
- **Drift that may already exist (please check):**
  - The stat and resistance sums read the loadout slots directly (`Loadout.PrimaryWeapon`).
  - The effect gathers go through `GetActiveWeapon()`, which follows `bShowPrimary`.
  - So a Generic with a primary weapon, no secondary, and `bShowPrimary == false` gets that weapon's stats and resistances but not its effects.
- **Risk:** any new class rule (Resonator's "≤3 same element", B-024 slot changes) must be edited into 5 places identically.
- **Single source:** a `ForEachContributingGear(TFunctionRef<void(const FGearContribution&)>)` on `ULoadoutComponent`. It yields the weapon entry, ring entry or evolution plus its instance tier, and is used by all five readers and the debug print.
- **Files:** `LoadoutComponent.h/.cpp` (2), plus `SkillEffectManager.cpp` for the debug print (3). One cluster.
- **Check:** `wor.CompareStats` and the effects specs come out identical. Decide the `bShowPrimary` case first (below).
- **Question Q-a:** should stats, resistances and effects all follow `GetActiveWeapon()` (the weapon actually in hand)? The reference-backed default is yes. In Expedition 33 and FF-style weapon swaps, only the drawn weapon's passives apply.
