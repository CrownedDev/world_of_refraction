# PIE — B-549: one-player stage 2, the class table (align the data)

**Branch:** `feature/B-549-class-table-stage2` (in dev, built and tested on the desktop 2026-11-16).

**What it is:** the class defaults asset (`DA_Loadout_ClassDefaults`) gains the class table (D-228): per class, its world levels, action speed and portrait; a Refractor (Caster) has one row per element choice, Broken Darkness its own, with the innate spells and BD pools. It is filled once from today's 12 Lords with an editor button. Nothing reads it yet: stage 3 builds the player from it and the picks, so the game plays exactly as before.

**Not in this stage:** resistances stay in the C++ table (`ClassInnateResistanceTable`); the new-game pick lists (a Generic's weapons, a Resonator's crystal types) stay on the stage 1 stub until stage 4 gives them gear. Reality has no Lord to fill from (D-095), so it has no row yet.

**Editor steps first (Crown or the editor session):**
1. Open `DA_Loadout_ClassDefaults`. Under **Class table | Fill**, add the 12 `DA_Character_*` Lord assets to **Fill Sources**, click **Fill From Sources**, then save the asset (Fill Sources is not saved).
2. Create `DA_Character_Player`: duplicate one cast character asset, set **Origin** to Player. Nothing reads it until stage 3.
