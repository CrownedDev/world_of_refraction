# PIE — B-040: gameplay tags (GAS stage 1)

**Branch:** `feature/B-040-gas-tags` (in `dev`).
**Already proven:** the editor builds and every test passes. `WoR.Tags` checks that every element and class has its own tag and maps back, that a Stun, a heal block and an all-status immunity give the matching tags, that the tags agree with the old checks, and that a tag goes when its effect goes.

**Note:** for now the tags are built from the same effects the old checks read, so `wor.CompareTags` mostly proves the maps are right; it becomes a real cross-check when the Ability System Component owns the tags (stage 2).

**What changed:** nothing you can see in play. The game now has a named tag for every element, class, status and immunity, the groundwork for the Gameplay Ability System. Two console commands let you check them.

**Setup:** any fight. Open the console with the tilde key; Output Log open.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Type `wor.DumpTags` | One line per element, class and status, e.g. `Fire -> Element.Fire`; no line says ROUND-TRIP FAIL | [ ] |
| 2 | At the start of a fight, type `wor.CompareTags` | Green on screen: 0 of N combatant(s) disagree; each combatant logs tags agree (no tags) | [ ] |
| 3 | Stun or Silence an enemy, then type `wor.CompareTags` | Still 0 disagree; that enemy logs Status.Stun or Status.Silence | [ ] |
| 4 | Play a full fight as usual | Nothing behaves differently from before | [ ] |
