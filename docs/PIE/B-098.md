# PIE — B-098: weapons stop giving spells (D-027)

**Branch:** `feature/B-098-weapons-no-spells-cloud` (cloud pre-write on top of B-097, **UNBUILT**: the desktop builds, runs the specs and merges; merge B-097 first).
**Already proven by tests (once built):** `WoR.Loadout.WeaponsNoSpells`: a weapon crystal's spells are not listed, slotted, picked, castable or in the menu for a Generic, a Refractor or a Resonator; the weapon's abilities still are; the data stays; `wor.Loadout.WeaponSpells 1` lists them again. `WoR.Combat.BrokenSources`, `WoR.Loadout.SpellSlotList` and `WoR.Loadout.GearChangeDrops` now run with the old path on and keep their checks.

## Survey (the job's first deliverable)

Where weapon spells came from, and what B-098 does with each:

| Where | What it was | Now |
|---|---|---|
| `FWeaponLoadoutEntry::GetAllSpells` (the crystal's built-ins + the loadout's `AssignedSpells`, or the edited list) | The one list every reader used: `FCombatLoadout::GetAllSpells` → `ULoadoutComponent::GetAvailableSpells` (AI `AIDecisionManager.cpp:62`, cast checks `ActionExecutor.cpp:5108`, `CombatPlayerController.cpp:297`, combat tier `CombatTier.cpp:66`), the primary / secondary slot lists, `ResolveSpellSource`, `FindSpellCatalystHolder` | Empty (`WeaponSpellRules`) |
| `FWeaponLoadoutEntry::GetSpellSlots` / `ReplaceSpell` (B-351d's one list per crystal) | The loadout screen's weapon spell slots | Empty / refused |
| `FCombatCapabilities::BuildFrom` (`WeaponCrystalSpells`, `bHasWeaponCrystal`) | The **Resonate Weapon** spell submenu (old and new HUD) | Off; Resonate Weapon shows only for augment-stone abilities |
| `ULoadoutComponent::GetWeaponResonateSpells` | Evolved weapons' resonate spells | Empty |
| Data: `FWeaponInventoryEntry::AssignedSpells` / `SpellPicks` / `bSpellSlotsActive`, `FWeaponLoadoutEntry::AssignedSpells` | Weapon spells in assets, the pool and saves (`SaveSubsystem.cpp:129-183`, run layer `PoolRunLayer.cpp:107`) | **Kept, unread** (Q-098): old saves load unchanged; no save version bump |
| `ULoadoutComponent::CreateAndConfigureLoadout` (`LoadoutComponent.cpp:390`) | Puts given spells on a weapon primary (no C++ caller) | Writes data nothing reads; dropped in the sweep |
| Loadout validation (`LoadoutRules.cpp:193-222`, `LoadoutComponent.cpp:697`, `1126`) | Checks weapon spells are learned / under the cap / fit the element | Unchanged (it checks data only; findings on an unread list are harmless; swept with the fields) |
| Weapon crystal as an infusion source (`ActionExecutor.cpp:4575`) | Keys the weapon's abilities' element (B-080) | Unchanged: this is D-027's replacement |

In-game data: `wor.Loadout.ListWeaponSpells` lists every owned weapon that still holds spells. Weapon *assets* with built-in spells come from their crystal (`CrystalEffectTable`), not the weapon asset: no asset edit is needed.
