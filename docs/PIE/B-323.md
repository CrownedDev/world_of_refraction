# PIE — B-323: give between characters

**Branch:** `feature/B-323-give-between-characters` (written unbuilt in a cloud session, **stacked on `feature/B-322-per-character-pouch`**; the Unreal writer merges B-322 first, then this).
**To be proven by tests (once built):** `WoR.Pool.Give` (a given dagger leaves A and is B's, A's worn secondary comes off; A's primary refused; not-yours and self-give refused; a copy B already owns wakes B's duplicate choice; part of a stack moves; a full pouch refuses a new type but takes one it already stacks). `WoR.Pool.SharedGear`, `WoR.Pool.ItemSlots`, `WoR.Economy.DuplicateGear` still green.

What changed for play:
- A character can **give** a weapon, adapter or pouch stack to another member of your party (`wor.UI.Give`). One instance moves.
- Worn gear comes off the giver's loadouts as it goes. A loadout's **primary** can't be given (swap in another first).
- If the receiver already owns a copy, the Output Log says so and `wor.UI.Duplicates` offers the choice.
- Evolutions can't be given yet (Q-323).

**Setup:** pull the branch, build, run the tests. Start PIE in the hub with a party of two or more; make sure member A owns a spare weapon (not its primary) and carries some items.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | `wor.UI.Give` | `From: <A>`, the first item A could give, `To: <B>`; Next giver / Next item / Next receiver cycle | [ ] |
| 2 | Pick A's spare weapon, press **Give** | `Gave <name>`; Output Log `[Pool] <A> gave <guid> to <B>`; A's loadout no longer lists it; B's armoury does (`wor.Inventory.Print` or the loadout screen) | [ ] |
| 3 | Pick A's primary weapon, press Give | `That is a loadout's primary. Swap in another primary before giving it`; nothing moves | [ ] |
| 4 | Give B a weapon B already owns a copy of | Output Log `received a second <name> - choose Gold or dismantle`; `wor.UI.Duplicates` on B's pawn shows the pair | [ ] |
| 5 | Pick a pouch stack, press **Give** then **Give the stack** | One, then the rest, move to B's pouch (`wor.Inventory.PrintSlots`) | [ ] |
| 6 | Fill B's pouch (10 types), give B a new type | `<B>'s pouch has no room for <item>` | [ ] |
| 7 | Set the receiver to the giver, press Give | `Choose another character to give to` | [ ] |
| 8 | Give with a giver who isn't spawned in this level (if the hub has such a member) | The give goes through; at that member's next spawn the log warns it refilled its primary if the given piece was one | [ ] |

**Could not be verified in the cloud (no Unreal):** compile and the test run; whether `HandlePoolGearChanged` runs on the giver before the receiver (both are bound to the same delegate; the order doesn't change the result); `TActorIterator` cost in `FindMemberInventory` is per give, not per tick.
