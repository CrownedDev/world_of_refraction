# PIE — B-554: one-player stage 3a, the player built from the picks; one save file per character

**Branch:** `feature/B-554-player-from-picks` (in dev, built and tested on the desktop 2026-11-17). **Built unseen** (overnight run): nobody has looked at it in PIE yet.

**What it is:** Begin on the new game screen now builds the player from the picks (D-228): the shared `DA_Character_Player` copied, named by what it is (its class and element, such as Fire Refractor; D-228, 2026-11-17: no typed name), the picked class, the Refractor's element (Broken Darkness and Reality among them) and the class table's world levels, action speed and portrait (`DA_Loadout_ClassDefaults`, B-549). The asset's own name and class (still the Generic copy's) are never used. The picks are saved with the party, and the player is built again from them on every load. Each character has its own save file (D-229): the title lists every filled slot, then the + while there is room (`[WoR.Title] MaxCharacterSlots`, default 12). Continue on a slot loads that character; the + starts a new one in the first free slot and leaves the others alone; delete removes only that slot's file.

**Action speed:** the class table's 0 (the Resonator and every Refractor row, as the old Lords had) is the normal speed: no Action Speed points, ×1.0, the animations play at their own pace. The Generic's 40 makes it faster. The table's numbers are unchanged.

**Not in this stage:**
- the kept last-run levels (D-237: B-555);
- gear from the picks (stage 4). Until then the built player carries the old start character's inventory (the matching Lord's: its innate spells and starting gear), the same kit as before;
- the character figure on the title (stage 3b).

**Save version 44:** older saves are wiped on load with the "Your save was reset" notice (D-060).

**Editor steps:** none. `DA_Character_Player` exists (stage 2), and `DefaultGame.ini` points the game at it (`[/Script/world_of_refraction.PartySessionSubsystem] PlayerCharacter`).

**Known limits:**
- Co-op (stage 5): a client restoring a checkpoint also builds "WoRPlayer" and would rename its own player's copy away. Joining is not changed until stage 5.
