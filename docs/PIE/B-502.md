# PIE — B-502: rest points are the services

**Branch:** `feature/B-502-rest-points-are-services` (in dev, built on the desktop 2026-11-14).
**What it is (D-214, Q-502):** a rest point that no boss left is also a service. You rest there and use it from the same menu. An **anvil** is the blacksmith. A **shrine** sells pillar points: of the shrines in a trial, one sells each run (the same one for the whole run); the others only rest. **V** (himself, or his mirror) extracts the party. Boss rest spots are unchanged. The test boxes stay until the art.
**Already proven by tests:** `WoR.Trial.RestService` (the prompt names the service; one of the placed shrines sells for the whole run and only there, not after stepping away; V's rest point extracts where a plain one can't; a mini-boss's rest spot has no service).
**Not proven:** the menus on screen. Nothing was seen running from the writer's worktree.

## Editor steps (for the editor worker)

In `TestLevel_Trial_01` (and later each trial map), on each purple rest point box that no boss leaves:

1. Select the rest spot, Details > **Rest Spot > Service**: one **Blacksmith (an anvil)**, one **Extract (V, or V's mirror)**, and the rest **Pillar shrine**. Place at least two shrines, or the one shrine sells every run.
2. On the Blacksmith rest spot set **Service Merchant** to the blacksmith's merchant asset (the one the hub's Blacksmith uses). Without it the shop opens with nothing to buy.
3. The shop-coloured boxes beside the rest points are still `ATrialNPC` actors. Replace each with a plain coloured box (a static mesh, no actor class), so the colour still shows which service it is and nothing else can be talked to. Do this after checks 1 to 8 pass; the old V box still extracts until then.

Before step 1 is done, the console does the same for one PIE session: stand near a rest point and run `wor.Trial.SetRestService anvil`, `shrine` or `v` (`none` clears it). `wor.Trial.PrintRestSpots` lists every rest point, its service and which shrine sells this run.
