# PIE — B-034: infusion level held on the pending action

**Branch:** `refactor/B-034-infusion-level-on-pending-action` (merged into `dev`).
**Already proven by tests:** `CommandMenuKeysSpec` checks that a target picker opens at L0, that the level key cycles L0 → L1 → L2 → L0, that the VFX component shows the same level as the menu, and that leaving the picker resets it to L0. The full suite (632) is green.

What changed:
- The command menu now keeps the infusion level of the action you're picking. The infusion VFX on the character only shows it.
- `InfusionChargeManager` (the old hold-to-charge system) is marked obsolete. It is deleted in B-034b, after checking in the editor that no Blueprint uses it.

**Setup:** pull `dev`, build, open the editor, start the demo fight.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Pick an ability, then press the infusion level button (or key) three times | The button reads L1, L2, then L0; the weapon VFX grows at L1, more at L2, and goes off at L0 | [ ] |
| 2 | Set L1, cycle the source, confirm on a target | The VFX switches to the new source; the hit uses that source's element and the L1 cost | [ ] |
| 3 | Set L2, press Back, pick the ability again | The picker opens at L0 and the VFX is off | [ ] |
| 4 | Pick a spell from a crystal, set L1, cast it | The spell is cast infused at L1 (cost and log line `level(spell/ab)=1/0`) | [ ] |
| 5 | Pick an item | No infusion buttons | [ ] |

**Notes:**
- No behaviour change is intended. If anything differs, it's a bug.
