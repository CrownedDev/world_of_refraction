# PIE — B-151: one wallet per player

**Branch:** `feature/B-151-player-wallet` (in `dev`).
**Already proven:** the editor builds and every test passes. `WoR.Economy.PlayerWallet` checks that both party members (one played by the AI) use the player's wallet, two characters spend from one balance, essences are shared, and an actor with no player behind it keeps its own wallet.

**What changed:** D-046. Your party has one wallet (Gold, Prisms, Diamond, every essence), held by your player, not by each character. Fleeing takes its Gold share once. Where the wallet lives is Q-151. It still resets on a level change, as each character's did before, and it isn't saved yet.

**Setup:** a trial with a party of two (recruit a member first). Output Log open. `wor.Wallet.Print` prints the wallet your pawn uses.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | In the trial, run `wor.Wallet.Print` | "[Wallet] <your pawn> uses the player wallet (<...PlayerState...>)" | [ ] |
| 2 | Win a fight where a crystal breaks on the AI ally, then `wor.Wallet.Print` | The essence from the break is in your one wallet | [ ] |
| 3 | With some Gold, flee a fight | Output Log "party lost N Gold": one share of the wallet, not one per member | [ ] |
| 4 | Open a shop in the trial | The shop shows the one wallet's balance; a purchase spends from it | [ ] |
| 5 | In the hub, run `wor.Wallet.Print` | "player wallet". If it says "own component", the hub's Blueprint game mode needs Player State Class = WoRPlayerState (Q-151) | [ ] |
| 6 | In the battle level, run `wor.Wallet.Print` with an AI ally in the party, then let a crystal break on the ally | Your pawn uses the player wallet; the ally's break essence lands in that same wallet | [ ] |
