# PIE — B-459a: the host-lost card and Hand over host?

**Branch:** `feature/B-459-coop-session-screens` (in dev, built 2026-11-14).
**Mockups:** `docs/Design/screen_mockups/coop/session/3_host_lost.png`, `4_planned_handover.png`.
**Already proven by tests:** `WoR.UI.HostHandOver` (3 cases): the card per hand-over step (title, who hosts next, pips, Stop waiting only while waiting on someone else); the confirm refuses a guest or a host alone and names the next host; the lost-host signal fires when a hand-over starts and when the player stops waiting. `WoR.Coop` still passes (the hand-over itself is unchanged).
**What changed:** the hand-over now tells the game each step (the lost-host signal). While it runs, every player sees a card: "The host left" (or "Handing over host" when planned), who takes over, four pips and the step (leaving the old session, reopening the trial, looking for the new host). B / Esc stops waiting while you wait on someone else. The rest menu's "Hand over host" now asks first: "Hand over host?" names the next host; A hands over, B stays host. Decisions: **Q-459a** (reference-backed default).
**Not checked by me (needs your eyes):** everything with two machines (I can't run co-op here); the look; that input comes back after the card closes.
**Left out:** the next host's name on the card (it reads "The next player"); "Leave to the Void Realm" (B is "Stop waiting"); the Invite screen and the join request card (B-459b, B-459c).

**Setup:** pull `dev`, build, two machines (or two PIE windows as listen server + client) in one co-op session at a rest spot.
