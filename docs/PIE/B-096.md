# PIE — B-096: evolutions that raise the run-end payout

**Branch:** `feature/B-096-payout-passives` (in dev, built 2026-11-12; cloud pre-write `-cloud`).
**Already proven by tests:** `WoR.Trial.RunPayoutPassives`: worn bonuses add up from any place, a broken evolution gives nothing, the multiplier is base + percent capped at x2.0, and a fighter's worn evolution raises the run-end payout after the fight-end refresh, only inside a run. `WoR.Trial.RunRewards` still passes (B-073).
**Setup:** in the editor, pick any evolution asset you can equip and set **Rewards → Run Payout Bonus Percent** to `25` (save it, or undo after the check). Q-096 rules: bonuses add up across the party, cap x2.0, read at the end of each fight.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Start a trial run on Medium with **no** payout evolution worn; win a fight; `wor.Trial.PrintRewards` | Multiplier x1.00 | [ ] |
| 2 | At a rest spot (or before the run), equip the 25% evolution on a character's own slot; win another fight; `wor.Trial.PrintRewards` | Output Log: `[TrialRun] Payout passives: +25% -> run-end multiplier x1.25`; PrintRewards shows x1.25 and the end payout is the tally x1.25 | [ ] |
| 3 | Put the same evolution in a weapon's socket instead; win a fight | Still x1.25 (it counts wherever it is worn) | [ ] |
| 4 | Give two characters 25% evolutions (or set one to 150); win a fight | x1.50 with two; x2.00 at most (the cap) | [ ] |
| 5 | Lose a fight while wearing it so the run ends; back in the hub | Hub Gold / essences went up by the tally x the multiplier (plus difficulty) | [ ] |
| 6 | Let the evolution break in a fight (wear it to 0) | After that fight the bonus is gone (multiplier back down) | [ ] |
