# PIE — B-031: rituals on the async path

**Branch:** `refactor/B-031-async-only` (in `dev`).
**Already proven:**
- The editor builds and every test passes, including the new `WoR.Combat.RitualFire` spec.
- The spec checks that:
  - an armed ritual fires exactly once on its Execution turn, and the fight moves on to a normal turn
  - a ritual that can't fire moves the turn on and is never left hanging (checked by breaking the code on purpose: the test then fails)

**What changed:**
- A ritual now fires through the same path every other action uses. The old path dropped a ritual ability or spell that has no montage (and, for a ritual Defend that failed, advanced the turn twice).
- The debug "execute test action" uses the same path too.
- `SubmitAction` (the old path) is marked obsolete. In Blueprints it now shows as deprecated. It is deleted later with `CombatOrchestratorTestActor` (B-165).
- Not covered by a test: the no-montage ritual ability. Its test crashed in the headless test world (B-166), so check it here.

**Setup:** open the editor on `dev`, open the Output Log, and give a character a skill with an **Activation Delay** above 0 (a ritual).

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Start a fight and use the ritual skill | The log shows `Ritual armed`; the turn ends | [ ] |
| 2 | Play turns until the ritual is due | The log shows `Execution turn: firing ...`, the skill plays and hits, then the next character's turn starts. No freeze | [ ] |
| 3 | Do the same with a ritual skill that has **no montage** (if one exists, or temporarily clear one's montages) | It fires and resolves (before, it was dropped silently). Note what you see | [ ] |

| 5 | Open any Blueprint that calls **Submit Action** (if any) and compile it | A deprecation warning, no error. Tell Claude which Blueprints call it | [ ] |
