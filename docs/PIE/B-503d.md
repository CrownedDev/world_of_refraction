## Editor steps (for the editor worker)

The new command and the new limit are in the code, so the main checkout needs a rebuild first, **with the editor closed** (the open editor holds the game's DLL, and the build can't replace it).

1. Close the editor. Pull dev on the main checkout. `Scripts/ue/build.sh`.
2. Still closed, the swing (B-503b): `UnrealEditor-Cmd <uproject> -run=pythonscript -script="Scripts/editor/build_light_hit.py" -unattended -nullrhi`. It builds and saves `AM_SAS_LightHit_Field` and sets it on `DA_SAS_Attack_LightHit`.
3. Open the editor. In its console: `wor.Editor.BuildFieldPulseMontage`. The Output Log should say `[LightHitBuilder] built ...AM_Field_Pulse: 1.200 s, 1 notifies` and `release at 0.50 s of 1.20 s`. **The command doesn't save:** save the new asset (`/Game/Data/Skills/Field/Pulse/AM_Field_Pulse`).
4. Open `AM_Field_Pulse` and preview it on the map character's mesh. It is the right hand's throw (4.0 to 5.2 s of the clip), with `Impact0` at 0.5 s, when the hand is at full speed. Move the notify or the segment's start and end if the release looks early or late. **Check that it plays at all:** the clip is on the magic pack's skeleton (`/Game/Imports/Animations/MagicAnimations/Demo/Mannequins/Meshes/SK_Mannequin`), the map character's mesh `SKM_Manny_Base` is on `SK_Manny_HTS`, and neither lists the other under Compatible Skeletons. The battle's spells already use that pack's clips on this character, so it is expected to play by bone name, with the pose sitting a little differently. If the character doesn't move in check 3, add the magic pack's skeleton to `SK_Manny_HTS`'s Compatible Skeletons, or retarget the clip and tell the writer the new clip's path.
5. In `Config/DefaultGame.ini`, under `[/Script/world_of_refraction.FieldMovementComponent]`, uncomment `FieldPulseMontage` and `FieldPulseVFX` (the paths already match `AM_Field_Pulse` and `/Game/VFX/Field/FXS_Field_Pulse`). Restart the editor: these two are read at start-up.
6. In `DA_BattleTransition_Default`, Timing: **Blow Away Ease** now accepts 0.3 to 6.
