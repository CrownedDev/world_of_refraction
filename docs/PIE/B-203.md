# PIE — B-203: the party's item slots and storage

**Branch:** `feature/B-203-item-inventory-storage` (in `dev`).

**Already proven:**
- The editor builds, and 574 tests pass; data validation shows no new errors.
- `WoR.Pool.ItemSlots` (8 cases):
  - an 11th item type goes to storage, and moving it back fails until a slot is free;
  - what doesn't fit a full stack (10) goes to storage;
  - two party members see and use the same carried items;
  - a member's add is never refused for space;
  - a character's starting items go in once, and a level reload doesn't add them again;
  - a fight's auto-equip takes from the carried items, and the unused ones come back after it;
  - an enemy keeps its own crystals;
  - the carried items, the slot count and who is banked survive a save.
- Not provable headless: a real party spawning, a real fight, the placeholder screen and a restart. These checks cover them.

**Setup:** start PIE in the hub with a party (recruit one or two, as in B-071). Open the console with the tilde key, and keep the Output Log open. `wor.Inventory.PrintSlots` dumps the carried slots and storage. **Placeholder screen:** `wor.UI.ItemStorage`.
