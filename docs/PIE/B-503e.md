# PIE — B-503e: the field keys work with no editor step

**Branch:** `fix/B-503e-field-input-in-code` (in dev, built and tested on the desktop 2026-11-15).
**What it is:** left click did nothing on the trial map because B-214g's input assets (`IA_Field_Attack`, `IA_Field_SwitchSource`, `IA_Field_FlyVertical`) were never made. Now the hub controller makes them in code with the keys in `docs/Design/InputMap.md`, so nothing has to be done in the editor:
- **Field attack:** Left mouse / RB. A tap attacks; held 0.4 s or more, the held attack on release.
- **Cycle the field attack:** R / LB.
- **Fly up / down** (while flying): Space / A up, Left Ctrl / R3 down.

If someone later makes the assets and uncomments their lines in `Config/DefaultGame.ini`, the assets win. The keys aren't eaten, so Space still jumps.
**Not in it:** the field movement skill (double tap Shift / L3) still needs its asset, because a double tap is a trigger set on the asset; `wor.Field.Activate` stands in.

**Already proven by tests:** the full suite still passes. The keys themselves can only be tried in PIE.
**Not proven:** nothing seen in PIE.

## Editor steps

None. Pull dev on the main checkout and build with the editor closed.
