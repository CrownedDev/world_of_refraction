# PIE — B-235d parts 1-2: a memory goes to whoever found it, privately (Q-235d, Crown)

**Branch:** `feature/B-235d-private-memories-cloud` (cloud pre-write, built and specs green on the desktop 2026-11-08; in `dev`).
**Already proven by tests (once built):** `WoR.Memory.Sources`: who a memory is for, and Crown's rules 1-3 (finder, same character who met it, everyone's).
**Setup:** 2-player PIE (Play As Listen Server, 2 players) in a trial run; the host plays character **H**, the client **C**. Three memory assets with a fight-won condition "Character in the party": **M-C** (Character C, Character Depth lists C), **M-H** (Character H, lists H), **M-All** (a fight-won condition, lists no character).

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Win a fight with both characters | M-C: "New memory: …" on the client only; `wor.Memory.Print` on the host does **not** list it | [ ] |
| 2 | Same fight | M-H: the host's journal has it; the client is not told | [ ] |
| 3 | Same fight | M-All: both journals have it, each told on their own screen | [ ] |
| 4 | The log line for M-C | `host does not (a friend found it), 1 friend(s)` | [ ] |
| 5 | On the host, run `wor.Memory.Sent` | The client's characters (C) and the memories sent to them (M-C, M-All) | [ ] |
| 6 | Travel to the next fight and win it | Nothing above is announced again | [ ] |
| 7 | The host wins a fight alone (M-All unlocks for the host), then the client joins and both win the next fight | The client gets M-All then (a later finder still receives it); the host is not told again | [ ] |
| 8 | Solo (one player): win the same fight | All three memories behave as before B-235d (the host gets each whose conditions hold) | [ ] |

**Known:** a map spot, fragment, a worn item's or a reaction's memory still counts as the host's find (a client's press is part 3), so a friend gets those only when they list no character; a PriorMemory condition reads the host's journal for a friend; a memory the host collected in an earlier run is not shared.
