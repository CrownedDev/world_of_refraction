# PIE — B-529: the hub pawn stands as the party leader, so the starting gear is minted

**Branch:** `fix/B-529-hub-party-leader` (in dev, built and tested on the desktop 2026-11-16).

**What it is:** a bug from Crown's PIE. After a new game, the hub's pawn kept its class default ("Character Template") because only the trial maps' game mode stood the pawn as the party leader. So the Generic's StartingGear (B-522) was never minted in the hub. The trial kit became the first worn record, and the starting gear was skipped for good.
- **The fix:** the leader rule moved into a shared game mode, `AWoRGameModeBase`. `ATrialGameMode` now derives from it, and the hub's Blueprint game mode must derive from it too (editor step below).
- **The order guard:** a member who reaches a trial with no worn record gets its starting gear first. The run starts from that record, and the kit (per run, D-221) never becomes the first record.

**Already proven by tests:** `WoR.Party.HubLeader` covers:
- the hub pawn takes the leader's character and member id;
- the starting sword is minted once and worn;
- a trial wears the kit, and a quit puts the starting sword back;
- with no record, a trial start seeds the starting gear first.

Full suite in the session note.

## Editor step (before check 1)

The editor worker:
- **`BP_Hub_GameMode`:** the one `TestLevel_Nav`'s World Settings use. Two copies exist, `Core/Hub/` and `Blueprints/GameModes/`, so check which. Open Class Settings and set **Parent Class** to `WoRGameModeBase`, then compile and save.
- **After reparenting, check:** Player State Class keeps its value (the wallet). Game State Class reads `WoRGameState`. Use Seamless Travel is ticked (this also covers B-240).
- **If the Blueprint overrides `SpawnDefaultPawnFor`** in its graph, say so before removing anything: that override would skip the leader rule.
