# PIE — B-439b: a quit run also takes back the items found in it

**Branch:** `fix/B-439b-quit-takes-pouch-finds` (in dev, built 2026-11-14).
**Already proven by tests:** `WoR.Pool.RunLayer` (2 new cases): a quit takes back what the run found, from the pouches first and then storage; what was carried or stored before the run stays; an item used in the run isn't charged twice; a run that ends any other way keeps its finds; a recruit's starting items are not finds. `WoR.Save.RunLayer`: an item found before a save is still taken when the resumed run is quit.
**What changed (Q-439 point 2, D-176):** quitting a run from the game menu used to keep the crystals and stones picked up in it. Now they go too: for each kind, whatever the party holds above what it held when the run began is taken back.
**Decided by default (Q-439b, Crown may change any):** it is counted for the whole party, per kind (a kind already owned keeps its old count, wherever the items now sit); pouches pay first, then storage; a find that overflowed to storage is taken too; an item used during the run is not charged again; a recruit's starting items are not finds. Extracting, winning and running out of wipes take nothing (what a wipe-out keeps is B-451).
**Old saves:** a run saved before this build and resumed now treats everything held at the resume as owned (start a fresh run for these checks).
**Not proven by a test:** the one line that makes the game menu's Quit call this (checks 3 and 4 are that proof).
**Not covered:** a co-op guest's own pouch (only the host can quit, and the guest's items live on the guest's machine).

**Setup:** pull `dev`, build, open the editor, PIE in the hub.
