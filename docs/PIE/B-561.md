# PIE — B-561: a co-op guest joins with its own character's picks (one-player stage 5, part 1)

**Branch:** `feature/B-561-guest-joins-with-picks` (in dev, built and tested on the desktop 2026-11-17). **Built unseen** (overnight run): nobody has looked at it in PIE yet.

**What it is:** the host side of a guest joining as its own built character.
- The guest sends the host its picks: class, element, weapons or crystals, body (`AWoRPlayerState::RequestJoinWithPicks`).
- The host builds the character from its own class table, under a guest name of its own (`WoRPlayer_Guest_<player name>_<class>_<element>`; D-228, 2026-11-17: the joining player's online name, no longer the typed name), so it never takes the host player's name. On screen it is named by its class and element.
- The host files today's join request with it (D-150): the host still picks the AI seat it takes, as before.
- The seated member keeps the picks. The host's save builds it again on load, and a trial lays the picks over its class kit.
- A guest that leaves and comes back with the same picks gets the same character back (the same gear key).

**How to reach it:** the guest's menu button is B-562. This part has no button of its own.

**What only the spec proves (no second client was run overnight):** the guest name, the find-again, and a refused empty join. The RPC over the network, the host's seat and the guest's control of the member are **unproven** until a two-player PIE.

**Defaults chosen (Crown may change), Q-561:**
- The guest's character is built on the host from the host's class table; the guest's word is trusted for its picks (the co-op trust TODO).
- Two guests with the same player name, class and element would share one character.
- A guest coming back under the same player name with other weapons or crystals keeps its first build.

Editor steps: none.
