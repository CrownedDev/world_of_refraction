# PIE — B-190: memory fragments

**Branch:** `feature/B-190-memory-fragments` (in `dev`).
**Already proven:** the editor builds and every test passes. `WoR.Memory.Fragment` (4 cases) checks four things: a memory is deep for one character, minor for another and nothing for the rest; picking up a fragment adds its memory to the run and the journal once and removes the fragment; a fragment taken earlier in the run is still gone when the level reloads; a fragment with no memory picks up nothing.

**What changed:** a new `MemoryFragment` to place on a trial map. Press E next to it to pick it up: it says only "You found a memory fragment." (no hint about what it does) and disappears. Its memory goes into this run and into the memory journal, which keeps it even if the run fails (not saved between sessions yet).

**Setup:**
- Create a Memory Data asset (right-click > Miscellaneous > Data Asset > MemoryData). Give it a Title and Text, and in Character Depth add one character as Deep and another as Minor.
- Place a `MemoryFragment` on a trial map and set its Memory to that asset.
- Enter through the trial door. Have the Output Log open.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Select the Memory Data asset and click **Print Memory** in its Details | Output Log: its id, title, "Deep for <name>, Minor for <name>" | [ ] |
| 2 | Walk up to the fragment | Cyan hint "Press E to pick up the memory fragment" | [ ] |
| 3 | Press E | Yellow "You found a memory fragment." (nothing about what it does); the fragment disappears and the hint goes | [ ] |
| 4 | Run `wor.Memory.Print` | "This run: 1 memories [<id>]" and the journal line with its depths | [ ] |
| 5 | Win a fight in the trial, back on the map | The fragment is still gone | [ ] |
| 6 | Exit the trial, then run `wor.Memory.Print` in the hub | "This run: 0 memories"; the journal still lists it | [ ] |
