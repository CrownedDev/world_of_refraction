# PIE — B-234b part 1: the next player hosts when the host drops

**Branch:** `feature/B-234b-host-hand-over-cloud` (cloud pre-write, built and specs green on the desktop 2026-11-08; in `dev`).
**Already proven by tests (once built):** `WoR.Coop.HostSuccession`: the next host is the next player in join order; only a lost connection or a timeout starts a hand-over; a copy holding a run is adopted, and nothing else is.
**Setup:** three standalone instances (not PIE windows: a PIE client can't host): A hosts (`wor.Session.Host`), B then C join (`wor.Session.Find`, `wor.Session.Join 0`). A starts a trial run with B and C in the party and wins one fight, so both keep a copy (`wor.Coop.PrintCheckpoint`). The default map must be the hub (the run resumes from the hub). Best on separate PCs: instances on one PC share the save files, so B and C write the same checkpoint copy file (desktop review); if a step looks wrong on one PC, note it rather than fail it.
