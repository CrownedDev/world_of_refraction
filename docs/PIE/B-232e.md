# PIE — B-232e: a recruit fills a free spot in co-op, as an AI seat

**Branch:** `feature/B-232e-recruit-ai-seat-cloud` (cloud pre-write, built and specs green on the desktop 2026-11-08; in `dev`).
**Already proven by tests (once built):** `WoR.Party.TrialRecruit`: a recruit is an AI seat only in a networked session; solo it joins as a commanded member.
**Setup:** 2-player PIE (Play As Listen Server, 2 players), a trial run with a free party spot (2 members) and a recruitable character on the map (`wor.Party.RecruitForRun <CharacterData path>` on the host if none is placed).

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | The client walks to the recruit and presses E | Client log `recruit request sent to the host`; host log `a client's recruit accepted`; the party shows 3 members on both machines (`wor.Run.PrintState`) | [ ] |
| 2 | Start a fight | The recruit plays as AI (an AI seat) on both screens | [ ] |
| 3 | The client presses E on a party member | Nothing changes (dismissing is the host's) | [ ] |
| 4 | Solo run, recruit | You command the recruit, as before | [ ] |

**Review notes:** a host with a session open but nobody joined yet is already "multiplayer" (`NM_ListenServer`), so its recruits are AI seats too (D-150: a friend can take them); solo means no session (standalone). The recruit must be a placed or replicated actor for the request to reach the host (placed recruits are); `wor.Party.RecruitForRun` on the host is the fallback.
