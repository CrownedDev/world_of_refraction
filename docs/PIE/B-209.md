# PIE — B-209: more memory sources

**Branch:** `feature/B-209-memory-sources` (in `dev`).

**Already proven:**
- The editor builds, and 503 tests pass; data validation shows no new errors.
- `WoR.Memory.Sources` (7 cases): a boss drop unlocks once; a fired reaction unlocks its memory; a bound memory with an owner trigger only for its owner; one with an upgrade level when the item is levelled that far; one with both only when both hold; the owned gear's level counts over the loadout copy; a map spot unlocks once per run. Each lands in the run and the journal with its source. `WoR.Memory.Fragment` and `WoR.Story.Journal` still pass.
- Not provable headless: the real fight hooks, walking into a spot and the boss data found through the asset registry. These checks cover those.

**Setup (in the editor, needs saving):** a memory asset or two (`UMemoryData`), then:
- set `MemoryOnDefeat` on a boss data asset whose boss a trial fights;
- set `UnlockMemory` on a reaction in a `UReactionTriggerData` asset;
- on a weapon one of your characters wears, set `BoundOwner` and two `BoundMemories`: one with **Needs Owner Wearing** only (an upgrade-level one can't be reached in PIE yet, check 4b);
- place a `MemorySpot` on a trial map and set its Memory.
