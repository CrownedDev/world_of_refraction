# PIE — B-520: skills name what they need (D-224, skills track S2)

**Branch:** `feature/B-520-skill-gear-requirement` (in dev, built and tested on the desktop 2026-11-16).

**What it is:** stage S2 of `Design/AssetOverhaulPlan.md` (§5.2). Each skill now says which piece it needs to sit in: a weapon (any, or one type), an adapter (any, or one form), or an evolution (any, or one), and optionally a socket element. One rule (`SkillRequirementRules::IsMet`) checks it against the piece the skill sits in. Four places read it:
- **The Equipment screen** offers a piece only the known skills it meets (an axe skill isn't offered on a sword).
- **The loadout rules** flag a slotted skill whose piece no longer meets it.
- **The battle list** drops a weapon pick the weapon doesn't meet, and greys a ring or evolution spell it doesn't meet, with what it needs ("Needs: Phoenix Fire.").
- **The weapon entry's own check** (`ValidateAbilities`).

**Until the editor pass, nothing changes for abilities:** a skill whose requirement is not set yet (Kind "None (old fields)") reads the old fields, so an ability needs a weapon of its `RequiredWeaponType`, as before. One change shows now: a spell with `RequiredEvolutionCrystal` set needs that evolution (the field was never read before).

**Already proven by tests:** `WoR.Loadout.SkillGearRequirement` (the old fields, any weapon, a weapon type, an element, an adapter form, an evolution in the seat or in a ring, and the Skills tab offering only what the piece meets). Full suite 2251 passed, 0 failed; validation 16 known, 0 new.

**Not proven:** the screens and the battle list in PIE.

**Known limits:**
- The evolution seat's spells are greyed in battle when unmet, but the loadout rules don't flag them (there is no evolution-spell finding type yet).
- The skill's requirement is checked against the piece it sits in, not anything else worn (skills sit in a piece's slots, Q-520).

## Editor step (before checks 4-6): the scripted requirement pass

Set `GearRequirement` on every skill asset, in one scripted pass (editor worker):
- **Every ability:** `Kind = Weapon`, `bNeedsWeaponType = true`, `WeaponType` = its `RequiredWeaponType`. (A "use with any weapon" ability gets `bNeedsWeaponType = false`; none are known yet.)
- **Every spell with `RequiredEvolutionCrystal`:** `Kind = Evolution`, `Evolution` = that asset.
- **Every other spell:** leave it at `None`: it needs any spell source (an adapter with a crystal, or an evolution), as today (Q-520). Only a spell meant for adapters alone gets `Kind = Adapter`; none are known yet.
- Save all, then run validation (no new errors expected).
