# PIE — B-233b: invites, drop-in at rest spots, a leaving friend

**Branch:** `feature/B-233b-invites-drop-in` (merged into `dev`).
**Already proven by tests:** `WoR.Party.Coop` (B-233b cases): the seating rule (outside a run always; in a run only at a rest spot; a friend's own held seat always); a mid-run request waits away from a rest spot and is seated at one; a leaving friend's member turns into an AI seat held for it, and the same friend takes it back (same member, its sword stays its own); a held seat given to another player swaps like any AI seat. Not provable headless: the real logout, a leave mid-fight, the invite screen, and invites (no friends list on LAN).
**Setup:** 2-player PIE, **Run Under One Process off**, Play As Listen Server (or two standalone instances on one network with `wor.Session.Host` / `wor.Session.Find` / `wor.Session.Join 0`). A party of the host's leader plus at least one AI seat (`wor.UI.PartyControl`). Q-233b (the reference-backed answers) is in `docs/DesignDecisions.md`.
