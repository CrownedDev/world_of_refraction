# PIE — B-042d: GAS stage 3, part 4 (combat GameplayEvents)

**Branch:** `feature/B-042d-gas-combat-events` (merged into `dev`).
**Already proven by tests:** `WoR.GAS.CombatEvents` (4 cases) checks that a hit, a resolved defense, a turn start and a turn end each send their `Event.Combat.*` event to the right fighter, from the right attacker, with the right number. It also checks that a fighter without GAS gets nothing and no error. The full suite (674) is green.

What changed:
- The game now sends a GAS event when a fighter is hit, defends, or starts or ends its turn.
- Nothing listens to the events yet. Later, skills will react to them through GAS abilities (B-043).
- `wor.Events.Log 1` prints each event to the Output Log.

**Setup:** pull `dev`, build, open the editor, start the demo fight.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Run `wor.Events.Log 1`, then play a turn where someone is hit and defends | `[CombatEvents] Event.Combat.TurnStart ...`, `Event.Combat.Hit to <target> from <attacker> (magnitude <damage>)`, `Event.Combat.DefenseResolved ...`, `Event.Combat.TurnEnd ...` in the Output Log | [ ] |
| 2 | Play the fight to the end | Everything as before; no new warnings or errors | [ ] |
| 3 | Run `wor.Events.Log 0` | The event lines stop | [ ] |

**Notes:**
- The magnitude on a Hit should match the damage number shown.
- Every combat character has GAS, so every hit and turn now goes through it. That's cheap with no abilities, but note any hitch or slowdown.
- A hit that kills still sends its event.
