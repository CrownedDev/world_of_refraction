# PIE — B-030: nothing from one fight carries into the next

**Branch:** `fix/B-030-reset-for-combat` (in `dev`).
**Already proven:**
- The editor builds, and every test passes, including the new `WoR.Combat.ResetBetweenFights` spec.
- The spec starts a fight, leaves a defense window open, an infusion charging and a turn-order preview built, then force-ends the fight. It checks that all of that is gone, and that the next fight starts clean.
- On the old code the spec failed: the preview still held 3 turns, the defense window stayed open, and the infusion was still charging into the second fight.

**What changed:**
- When a fight ends (win, loss or forced end), every per-fight system now resets itself:
  - the action still running (cancelled without resolving its defense windows)
  - defense windows
  - infusion charging
  - status bars
  - "once per fight" effects
  - the turn-order preview
  - the weather blend
  - a half-picked action in the command menu
- During a fight, nothing changes.

**Setup:** open the editor on `dev`, open the Output Log, and use a level where you can fight twice in a row (or restart a fight without leaving PIE).
