# PIE — B-153: Remove the OBSOLETE loadout `CharacterClass` field

**Branch:** `feature/B-153-loadout-class-field-delete-cloud` (cloud pre-write, UNBUILT, from `dev`). A deletion: **merge only after Crown's PIE of B-022** (CLAUDE.md: no deleting code before it's verified in PIE).
**Already proven by tests (once built):** the build compiles without the field, and `WoR.Loadout.Getters` stays green (it still checks `GetCharacterClass()` for every class; only the synced-field check is gone).

**What was deleted:** `ULoadoutComponent::CharacterClass` (a `UPROPERTY(EditAnywhere, BlueprintReadWrite)`), and its copy from CharacterData in `InitializeFromCharacterData`. Without CharacterData, `GetCharacterClass()` now gives `Generic` (the old field's default). A value saved for the field on a Blueprint's component or a placed actor is dropped silently on load: fine, because nothing in C++ read it while the owner had CharacterData (B-022).
