# PIE — B-042x: GAS stage 3, part 3c (status and immunity checks read tags)

**Branch:** `feature/B-042x-gas-tag-reads` (merged into `dev`).
**Already proven by tests:**
- New spec `WoR.GAS.TagReads`. With `wor.Effects.UseGAS 1`, each of these reads the character's GAS tag and nothing else, and with 0 none of them do:
  - stunned, silenced, has a burn;
  - heal-blocked;
  - stun, silence, burn and all-status immunity.
- A real stun reads the same with the switch on or off.
- `WoR.Effects.Baseline` already runs on both paths and is unchanged.
- The full suite (761) is green.

What changed:
- Nothing with the switch off (the default).
- With the switch on, the "has a burn" check and the character's tag list read GAS. The enemy AI's "one burn tick would kill" and "am I in danger (a stun or a deadly burn a cleanse would clear)" checks use them too. The stun, silence and immunity checks already read GAS (B-042c).

**Setup:** pull `dev`, build, start the demo fight. Open the console (`~`).

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Open the editor and watch the Output Log while it loads | No new errors | [ ] |
| 2 | Type `wor.Effects.UseGAS 1`. Stun an enemy (e.g. a Wind status break) | It skips its turn, as with the switch off | [ ] |
| 3 | With the switch on, put a burn on an enemy, then let the enemies act | Enemies don't stack a second burn on it, as before. A low-HP target with a burn is still picked off the same way | [ ] |
| 4 | With the switch on, give a character a heal block, then try to heal them | The heal is refused, as with the switch off | [ ] |
| 5 | With the switch on, give a character stun immunity, then try to stun them | No stun | [ ] |
| 6 | With the switch on, stun an enemy whose side has a cleanse | The enemy AI still treats the stun as dangerous (it may cleanse it), as with the switch off | [ ] |

**Notes:**
- No behaviour change is intended with the switch on or off. If anything differs, it's a bug.
