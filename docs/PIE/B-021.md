# PIE — B-021: one table for the stat stones

**Branch:** `refactor/B-021-stone-row-table` (in `dev`).
**Already proven:**
- The editor builds, and every test passes, including the new `WoR.Items.Stones` spec.
- The spec was written and passed on the old code first. For all 14 stat stones at every tier, used on an ally and on an enemy, it checks:
  - which buff or debuff the stone applies, how strong, and for how long
  - its name and element
  - which stat it boosts when attached
- Amber still gives its own Defense buff. It all still passes after the change.

**What changed for the player:** nothing. Each stat stone is now one row in a table instead of being listed in four separate switches. There is a new console command, `wor.PrintStoneRows`, which lists the table.

**Setup:** open the editor on `dev`, open the Output Log, and start a fight with a few stat stones on the item belt: a Luck Stone, a Defense Stone, a Resistance Stone, and Amber if you have one.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Type `wor.PrintStoneRows` | 14 lines, one per stat stone. ResistanceStone says `(own consumable handler)` | [ ] |
| 2 | Use a stat stone (e.g. Luck Stone) on yourself, then type `wor.PrintStatModifiers` | Your Luck shows a buff of the stone's percent (3% at F up to 15% at S) | [ ] |
| 3 | Use the same kind of stone on an enemy | The enemy gets the matching debuff (its Luck shows a minus) | [ ] |
| 4 | Use a Defense Stone, then Amber, on yourself | Both give a Defense buff. The stone's lasts 3 turns; Amber's strength and length are its own, as before | [ ] |
| 5 | Use a Resistance Stone on an enemy | Its status resistance goes down (it fills status bars faster), as before | [ ] |
| 6 | Attach a stat stone to your weapon | The stat it boosts goes up as before (`wor.CompareStats` before and after shows that stat changed) | [ ] |
