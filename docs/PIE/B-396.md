# PIE — B-396: the combat HUD is invisible in a fight (find the cause)

**Branch:** `fix/B-396-combat-hud-visibility` (desktop, 2026-11-09).
**Crown's report (PIE 2026-11-09):** in a trial fight nothing of the combat HUD shows. The log says it was built (`[CombatHUD] Built: 2 panel(s), strip=yes, menu=yes, prompt=yes`) and nothing tore it down until PIE stopped.
**What the code check found:** nothing in the merged cloud work (B-370, B-371, B-372 camera; B-228b client HUD; B-231, B-232b menu on the commander) hides, removes or covers the HUD on the host. The camera only changes the view target. The client HUD path does nothing on the host. The HUD widget assets have not changed since May. The build log of the 11-05 fight reads the same, line for line. So the cause has to be seen in PIE.
**What changed:**
- `wor.UI.Print` now prints, for every HUD widget: whether it is in the viewport, its visibility, its opacity, where it was drawn and its size, plus the game viewport's size. One print shows which of these is wrong.
- The trial gate's `Attempting to focus Non-Focusable widget` error is fixed (the gate can now take focus). That error came from the hub door, not from the fight.
