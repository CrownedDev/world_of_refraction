# PIE — B-361: recruits share the host's inventory; no skill trading between players (D-152, D-153)

**Branch:** `feature/B-361-recruits-host-inventory` (in `dev`; built on the desktop 2026-11-04).
**What changed:** a character recruited during a trial no longer has a pouch of its own: it carries the host's (the party leader in solo play), so what it picks up or uses is the host's. It now keeps and trades skills like any member (give, ask, buy a skill for it). When the run ends, every skill it had (its starting ones included, Q-361) goes to the host's character; one the host already knows stays one copy (Q-361c). A recruit brings no items (Q-361c). Between two different players' characters, skills can no longer be given or asked for; gear still can (it changes owner for good).
**Already proven by tests:** `WoR.Party.TrialRecruit` (a recruit's pickup lands in the host's pouch; it learns and gives a skill; its skills stay with the host at run end, one copy each; a skill give between two players' members is refused and a gear give is not), plus `WoR.Pool`, `WoR.Inventory`, `WoR.Economy`, `WoR.Shop`, `WoR.Party`, `WoR.Loadout`, `WoR.Save`.
**Setup:** PIE in a trial map with your party; the Output Log open. Recruit with `wor.Party.RecruitForRun <a CharacterData asset path>` (or a trial recruit spot).
