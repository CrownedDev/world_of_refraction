# PIE — B-110: a refused pick keeps the command menu open

**Branch:** `fix/B-110-menu-close-after-refusal` (in `dev`).
**Already proven:** the editor builds and every test passes. `WoR.UI.CommandMenu.Submit` checks that a stunned character's refused ability pick leaves the menu open for the same character (this test failed before the fix), and that the menu closes while a confirmed ability is still playing.

**What changed:** if the game refused an action you picked (for example a spell while stunned), the menu reopened and was then shut straight away, leaving you with no menu on your turn. Now it stays open so you can pick again. Normal actions close the menu as before.

**Setup:** for check 3, a fight where an enemy can stun your character; any fight for checks 1 and 2. Output Log open.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Pick an attack and a target | The menu closes while the attack plays; it opens again on your next turn | [ ] |
| 2 | Defend, then let the next player character act | The next character's menu opens and stays open | [ ] |
| 3 | While stunned, try a spell or ability through a menu that still offers it | Output Log "action invalid (...) - re-requesting"; the menu is open again for the same character; Attack or Defend works | [ ] |
