# PIE — B-503: the field attack cycles the whole loadout (D-215)

**Branch:** `feature/B-503-field-attack-loadout-cycle` (in dev, built and tested on the desktop 2026-11-15). Code only: no editor step of its own.
**Already proven by tests:** `WoR.Field.Attack` (6 tests): the cycle's order (weapons, then the innate element), the wrap, a broken crystal giving no element, the strike following the entry, the plain swing with nothing to cycle.
**Editor worker, before the checks:** Find in Blueprints for `Switch Field Attack Source`, `Get Field Attack Source` and `Get Field Attack Physical Type` (the three nodes this job removed). None is expected; a Blueprint that has one won't compile until the node is swapped for `Cycle Field Attack` / `Get Field Attack Entry`.
**Setup:** B-214g's editor steps make the key work (`IA_Field_SwitchSource` mapped to R / LB, the ini line uncommented). Without them use `wor.Field.CycleAttack` in the console: it does the same step and lists the whole cycle, but shows no popup. Play a trial map with a character that has more than one thing equipped (best: a weapon with a crystal, a ring, and an evolution).

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Press R (LB) once | A small box, bottom left, for 2 seconds: the next entry's icon, its name, and its element in the element's colour | [ ] |
| 2 | Keep pressing R (LB) | The gear in loadout order (the primary weapon or ring, the second weapon, then a Resonator's rings), then "Innate" (only for a character with an innate element), then every evolution; after the last it starts again at the first | [ ] |
| 3 | `wor.Field.CycleAttack` | The Output Log lists the whole cycle, the entry in use marked with `>`; weapons say `(swing)`, everything else `(pulse)` | [ ] |
| 4 | Cycle to an entry with an element, then field attack an enemy (Left mouse / RB) | The fight starts with the party first, and the enemies' status bars show that element's buildup | [ ] |
| 5 | Cycle to a weapon with no crystal, attack an enemy | The fight starts with the party first; no element buildup | [ ] |
| 6 | Cycle to a Water entry, hold the attack half a second, release | Ice in the log (as before) | [ ] |
| 7 | Cycle to the third entry, save, quit to the title, load | The same entry is still in use (`wor.Field.Print` or `wor.Field.CycleAttack` shows it) | [ ] |
| 8 | Switch the map character to another party member, cycle, switch back | Each character keeps its own entry | [ ] |
| 9 | With an entry far down the list in use, take gear off in the loadout screen so the list gets shorter | The attack falls back to the first entry; nothing breaks | [ ] |

**Since built:** the weapon's swing (B-503b, `docs/PIE/B-503b.md`) and the 7 m pulse (B-503c, `docs/PIE/B-503c.md`).

**Decided by default, Crown may change (Q-503):**
- An evolution socketed in a weapon or ring is its own stop (a pulse in its element), besides that weapon's own swing.
- "Innate" is only in the cycle for a character with a real innate element.
- A pulse carries no physical type (Slash / Pierce / Impact) into the fight; only a weapon's swing does.
- Cycling does not change the weapon in hand for the fight.
- The popup sits bottom left for now; it moves beside the party strip with the trial HUD.
