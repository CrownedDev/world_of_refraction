# PIE — B-500: battle transition, rough version

**Branch:** `feature/B-500-battle-transition-rough` (in dev, built on the desktop 2026-11-14).
**What it is (D-212, storyboard D):** a fight no longer cuts to the battle map. At contact the frame is captured, cracks from the hit point and breaks into thick 3D shards in front of the camera. The shards drift while the 2-second join window runs and the map loads, then blow past the camera onto the battle. Bloom, motion blur, depth of field and a small push in are on. No colour split (B-500b) and no sound (B-500c) yet.
**Already proven by tests:** `WoR.Combat.BattleTransition` (the shards cover the screen with no gap; the same seed rebuilds the same shards; the frame is whole at contact; a hold of any length never reaches the camera; the blow-away passes it; the clock stands still over the map change and ends by itself).
**Not proven:** how it looks. Nothing was seen running from the writer's worktree.

## Editor steps first (for the editor worker)

The shards' mesh and motion are made by code, so there is no mesh or Niagara effect to build. Until step 1 is done the shards are plain violet and show no frame: the motion and speed can still be judged.

1. **Shard material** `M_BattleTransition_Shard` in `Content/VFX/Transition/`. Surface, Opaque, Default Lit.
   - Texture parameter **`Frame`** (sampler type Linear Color), read with the default UV0. This is the captured frame; the code sets it.
   - `Frame` × a scalar parameter `FrameBrightness` (start at 1) into **Emissive**, so the picture reads true whatever the light.
   - Base Colour near black, Roughness about 0.15, so the bevels catch the light (the "thick and lit" look).
   - Vertex colour is there to use: **R** = 1 on bevels and sides (brighten the edges with it), **G** = a random per shard, **B** = distance from the hit point. B-500b's prism colours will use G and B.
2. **Data asset** `DA_BattleTransition_Default` in `Content/Data/Combat/`, class `BattleTransitionData`. Set **Shard Material** to the material above. Leave the other values at their defaults.
3. **Match the frame.** In PIE run `wor.Transition.Play`. At the first instant the shard wall should look like the screen did. If it is brighter or darker, change `FrameBrightness`; if it still doesn't match, try the asset's **Frame Capture Source** = "Final Color (HDR)".
4. Only if Crown finds the rough version flat: a Fab glass or crystal shatter pack as the base (D-212). Not now.

**Notes / what went wrong:**

- The boss arena's fight has no transition yet (it starts another way).
