# PIE — B-193: boss phases

**Branch:** `feature/B-193-boss-phases` (in `dev`).

**Already proven:** the editor builds and every test passes. `WoR.Boss.Phases` (6 cases) checks:
- the killing blow reaches no phase;
- a boss reaches phase 2 below its HP point and keeps it when healed to full;
- hidden conditions work (two status breaks; two of its own turns, while another combatant's turns don't count);
- one hit past two lines reaches both phases, and the weather pull rises with each;
- each break adds a step of status resistance, and each phase makes the AI one step harder;
- a boss with no authored phases uses its style's preset, and memories can skip or add a phase.

**What changed:** a new **Boss Data** asset gives a boss phases. A phase is reached when all its conditions hold, and it changes the fight: effects on the boss, AI steps, weather intensity. In a trial fight, any enemy whose character has Boss Data gets its phases. Dialogue, element change and added skills are only logged for now.

**Setup:**
- Create a Boss Data asset (Miscellaneous, Data Asset, BossData):
  - Boss: the trial's fallback boss character, or any enemy you can fight in a trial.
  - Phases: two entries.
    - Phase 1: PhaseId `Two`, Conditions [HP Below Percent, 50], AggressionSteps 1, WeatherIntensity 0.5.
    - Phase 2: PhaseId `Three`, Conditions [Turn Count, 4], WeatherIntensity 1.0.
  - Optional: give the boss a Caster class with a weather variant, so its sky shows.
- Output Log open.

| # | Do this | You should see | Result |
|---|---|---|---|
| 0 | Select the Boss Data asset and click **Print Boss Data** | Output Log: "Boss <asset> (<character>, style ...): 2 phase(s)", then a line for each phase with its conditions | [ ] |
