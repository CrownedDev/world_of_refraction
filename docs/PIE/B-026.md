# PIE — B-026: weapon and ring sockets share one code path

**Branch:** `refactor/B-026-gear-attach-template` (in `dev`).
**Already proven:**
- The editor builds, and every test passes, including the new `WoR.Inventory.GearAttach` spec.
- The spec was written and passed on the old code first. It checks:
  - a gem goes onto a weapon and a ring, and one is taken from your stack each time
  - a stone goes onto a weapon but a ring refuses it, and nothing is taken
  - an elemental fusion (stone + gem) goes onto both; a two-stone fusion goes onto a weapon only
  - a full slot, an unknown weapon or ring, an unowned crystal and an invalid fusion pair are all refused
  - an evolution goes onto one weapon or ring at a time; taking it off returns it with 10% wear, and if that wear takes it to 0 it is dismantled
  - removing a crystal by slot number empties the slot and destroys the crystal
- It all still passes after the change.

**What changed for the player:** nothing. The weapon and ring versions of attach and remove were two copies of the same code. Now each pair runs one shared version. The Output Log messages read the same, with "weapon" or "ring" filled in.

**Setup:** open the editor on `dev`, open the Output Log, and start somewhere you can open the gear/loadout screen with a weapon, a ring, a few gems and stones, and an evolution in your inventory.
