# PIE — B-562: a co-op guest joins from the game menu as one of its characters (one-player stage 5, part 2)

**Branch:** `feature/B-562-join-with-my-character` (in dev, built and tested on the desktop 2026-11-17). **Built unseen** (overnight run): nobody has looked at it in PIE yet.

**What it is (D-229, Q-561):** a guest in a friend's game (a network client) has a **Join the party** row in the game menu, just above Quit.
- It opens the title's slot list: the guest's own characters, read from its own save files, then the +. There are no Settings, Credits or Quit buttons, and no delete. **Back** closes it.
- **A** on a character sends that character's picks to the host (B-561). The host builds the character and picks the AI seat it takes, as before (D-150).
- The **+** opens the new game screen. **Begin** sends the new character's picks instead of starting a game.
- When the guest already plays a member, the row is refused with "You already play a member of this party."
- The host's own game menu has no Join row.

**What only the spec proves (no second client was run overnight):** the slot list without buttons, finding a save's character, the menu row (a guest's only, refused once seated). **Unproven** until a two-player PIE: the screens opening on the client, the guest's saves read there, the picks reaching the host, the seat.

**Defaults chosen (Crown may change), Q-561:**
- A new character made to join is **not** written to the guest's own slots. Make it on the title first to keep it.
- A character from before B-554 (a save with no picks) can't join; the screen says so.
- After **A** or **Begin** the screen closes. The host's answer shows as the seat, not as a message on the guest's screen.

Editor steps: none.
