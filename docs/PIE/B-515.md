# PIE — B-515: the shield is its own off-hand piece (D-223, asset overhaul stage 1)

**Branch:** `feature/B-515-shield-piece` (in dev, built and tested on the desktop 2026-11-15).

**What it is:** the first stage of the asset overhaul (`Design/AssetOverhaulPlan.md` §6). A shield used to be baked into the sword asset. Now it is a separate piece: a new weapon type, **Shield**, held only in the off hand.
- A Generic holds it with any one-handed (pairable) weapon, as a weapon set.
- The pair reads "Sword and Shield", attacks with the sword's attack, and stands in the sword's own stance (not the dual stance).
- The left hand shows the shield piece's own mesh.
- A shield can't be held alone or in the main hand.
- A D-209 pair (two axes) now also shows the second piece's own mesh in the left hand. Before, the left hand only showed a weapon's built-in left-hand mesh.

**Already proven by tests:**
- `WoR.Loadout.WeaponSets`: which pairs are allowed, the main-hand and alone refusals, the wield mode and the stance.
- `WoR.UI.GameNames`: "Sword and Shield" from a shield piece.

**Not proven:** the mesh in the hand, the Equipment screen flow and the battle, seen only in PIE.

## Before you start: the editor step (the editor worker does this)

1. Make `DA_Weapon_Sword` (under `Content/Data/`, in the weapons kind folder per ContentNaming):
   - Name "Arming Sword", Sword, F tier.
   - **Handling `SingleOrDual`**: it must be pairable to take a shield.
   - `WeaponAttack` `DA_Sword_Attack_LateralCut`, `WeaponStance` `DA_Sword_Stance_Basic`.
   - Mesh `SK_Sword_1H_Fantasy_01`.
   - No crystal.
2. Make `DA_Weapon_Shield` (next to it):
   - Name "Round Shield", **Shield**, F tier.
   - **Handling `DualOnly`**.
   - No attack, no stance.
   - `WeaponSkeletalMesh` `SK_Shield_Fantasy_01`, and set its `LeftMeshRotation` so it sits on the forearm.
3. Add both to the played character's inventory asset as spare `Weapons`.

The new assets come with the clean cast in stage 4.
