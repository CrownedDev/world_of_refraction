# PIE — B-439: the game menu (pause menu)

**Branch:** `feature/B-439-pause-menu` (in dev, built 2026-11-14).
**Mockups:** `docs/Design/screen_mockups/menus/pause/1_pause_trial.png`, `2_pause_hub.png`.
**Already proven by tests:** `WoR.UI.PauseMenu` (10 cases): the eight pages in order; which open and which say why not; a guest can't quit a run; the header in the hub and in a run (wipes left); a quit run pays nothing; the selection wraps; Resume closes; Quit asks first, holds only from the second press, stops when let go; Back leaves the question, then closes.
**What changed:** the Menu button opens a game menu in the hub and on the trial map: the place and its money on top, the page list, the party, a side panel for the focused page. Quitting a run loses everything from it (D-176). Nothing pauses.
**Not checked by me (needs your eyes):** how it looks, that the keys and gamepad reach it, and that you can move again after closing it. The engine's menu layer (B-103) has not had a PIE pass yet either, so this is its first real use.
**Not in this job:** Loadout, Character and Settings (they say "not built yet"); portraits; the tracked quest and loadout preview in the side panel; final art (flat colours and the default font for now).

**Setup (editor, once):**
- Pull `dev`, build, open the editor.
- In `BP_HubPlayerController`, **delete the `IA_ToggleMenu` nodes** in the graph (C++ handles the button now; with the nodes left in, the old handler fires too).
- If Back (gamepad B) does nothing in check 3, tell me: the menu also reads Esc, Backspace, B and Menu itself, so one of them should close it either way.
- In the editor, Esc ends PIE. Use the gamepad, or the console command `wor.UI.Pause` to open and Backspace to close.
