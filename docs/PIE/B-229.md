# PIE — B-229: inputs reach the server (co-op)

**Branch:** `feature/B-229-input-rpcs` (in `dev`; written in a cloud session, built and tested on the desktop).
**Proven by tests (once built):** `WoR.Coop.InputRouting`.
**Setup:** the battle's player controller must be an `ACombatPlayerController` (Blueprint) subclass, and the game modes must use `AWoRGameState` (B-228 setup). Play in Editor with **2 players, Listen Server**, and start a fight. The client has no combat HUD yet (B-228b), so its menu pick is made with `wor.Net.SendDefendPick`.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Single player (standalone): pick an attack, a spell with infusion level 2, and Defend from the menu | Each works as before; the Output Log has a `[CombatInput] ... local ... Accepted` line per pick | [ ] |
| 2 | Single player: Guard and Dodge an enemy attack | Guard and Perfect Guard land as before | [ ] |
| 3 | 2 players: on a party member's turn, run `wor.Net.SendDefendPick` in the **client's** console | The host's screen shows that character defending and the turn moves on | [ ] |
| 4 | On the host, run `wor.Net.PrintInputs` | The client's controller lists the pick as `[client] ... -> Accepted` | [ ] |
| 5 | On an **enemy's** turn, run `wor.Net.SendDefendPick` on the client | Nothing happens to the enemy; `wor.Net.PrintInputs` on the host shows `NotControlled` | [ ] |
| 6 | When an enemy attacks a party member, press Guard on the **client** at the impact | The Guard lands on the host's screen (a block or Perfect Guard), and `wor.Net.PrintInputs` on the host shows `[client] Defense ... -> Accepted` | [ ] |
| 7 | Press Guard on the client when no attack is coming | Nothing happens; the host logs `NoActor` | [ ] |

**Known limits:** a client's press that reaches the server after the impact has been judged misses (no server-side hold yet; B-231). In PIE the delay is near zero, so this shows only over a real connection. Until B-232, any player may command any player-driven party member (Q-229b).
