# PIE — B-022: loadout getters (no copy, class from CharacterData)

**Branch:** `refactor/B-022-loadout-getters` (in `dev`).
**Already proven:**
- The editor builds, and every test passes, including the new `WoR.Loadout.Getters` spec.
- The spec was written and passed on the old code first. It checks:
  - for Generic, Caster and Resonator, the loadout's class matches the character's CharacterData
  - the active loadout is the saved loadout at the active index, follows a loadout switch, and shows changes made to it
  - an out-of-range index gives an empty loadout
- It all still passes after the change.

**What changed for the player:** nothing. The game reads the active loadout without copying it each time, and reads a character's class from its CharacterData. The old `CharacterClass` field on the loadout component is still there and still synced, in case a Blueprint reads it. If a Blueprint *sets* it, that is now ignored for characters with CharacterData (their class always comes from the CharacterData).

**Setup:** open the editor on `dev`, open the Output Log, and start a fight with one character of each class if you can (Generic, Caster, Resonator). A Resonator with two or more rings is best.
