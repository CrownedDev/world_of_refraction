# PIE — B-360b: separate copies of one character (D-150 point 2)

**Branch:** `feature/B-360b-member-identity` (in `dev`; built on the desktop 2026-11-04).
**What changed:** two players may bring the **same character**. Each party member now has its own id; a second copy of a character already in the party is accepted (an invite or a join) and keeps its own gear, pouch, HP/EP, formation cell and commander. The first copy keeps everything as before (its gear is still keyed by the character asset, so old pools and saves read the same); a later copy's gear is keyed by its member id. The join refusal "already in the party" is gone. Save version 14 (every older save is wiped, D-138 / D-060). Not yet: a copy's victory levels go to the first copy's level-drop pool (B-360c).
**Already proven by tests:** `WoR.Party.Coop` (a copy gets its own slot, pool key, claim, roster entry and commander; a battle pawn stamped with the copy's id resolves to it and an unstamped one to the first copy; the save keeps both; two plain copies in a restored party get their own keys), `WoR.Save`, `WoR.Net.RunState`, `WoR.Pool`, `WoR.Inventory`; the subset green (204); data validation 0 new.
**Setup:** PIE with **2 players, Listen Server**, as `docs/PIE/B-360.md`: the host's party is you plus one **AI seat** (`wor.UI.PartyControl`). Both windows with the Output Log open.
