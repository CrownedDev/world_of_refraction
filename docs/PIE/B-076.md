# PIE — B-076: characters found in a trial join for that run

**Branch:** `feature/B-076-trial-recruits` (in `dev`).

**Already proven:**
- The editor builds, and 566 tests pass; data validation shows no new errors.
- `WoR.Party.TrialRecruit` (8 cases):
  - a recruit joins for the run only, and the run's end lets only it go;
  - its own gear never enters the party's armoury;
  - it holds the armoury weapon it was given, and wears it;
  - a Caster recruit keeps its innate spells and wears a given ring as its primary; a Resonator wears it in its ring loadout;
  - a recruit that leaves frees what it wore, and no recruit joins a party with no leader;
  - a weapon the leader wears stays with the leader, and the clash is noted;
  - the save keeps a recruit only with a run, and brings back its gear choice.
- Not provable headless: recruiting in a real trial, a recruit fighting, the placeholder buttons, and leaving the trial. These checks cover them.

**Setup:** start PIE in the hub with the leader only, and enter a trial. Open the console with the tilde key, and keep the Output Log open. Trial maps have no recruit spot yet (B-215), so recruit with `wor.Party.RecruitForRun <CharacterData path>`, using one of the hub recruits' character assets (copy its path from the Content Browser, e.g. `/Game/...` ). **Placeholder screen:** `wor.UI.PartyControl`. `wor.Party.Print` dumps the party, and `wor.PrintPool` the armoury.
