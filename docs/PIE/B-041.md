# PIE — B-041: GAS attributes (GAS stage 2)

**Branch:** `feature/B-041-gas-attributes` (in `dev`).
**Already proven:** the editor builds and every test passes. `WoR.GAS.Attributes` checks that a combatant's ability system gets its attributes filled from the stats, that they follow damage and a buff landing and going, and that a value that drifts is reported.

**What changed:** nothing you can see in play. Every combat character now has a Gameplay Ability System component that holds its HP, EP, status bar and stats as GAS attributes, kept equal to the real numbers. Groundwork for moving effects onto GAS (stage 3). Also fixed: clearing all of a character's effects at once (e.g. at the end of a fight) now updates their max HP/EP straight away.

**Setup:** any fight. Open the console with the tilde key; Output Log open.

| # | Do this | You should see | Result |
|---|---|---|---|
| 0 | Before playing: open each Blueprint child of `CombatCharacter` (player and enemy pawns) and compile it | No errors; the Components panel shows AbilitySystemComponent and AttributeSyncComponent (a name clash with an existing component or variable would show here) | [ ] |
| 1 | At the start of a fight, type `wor.CompareAttributes` | Green on screen: 0 of N combatant(s) differ | [ ] |
| 2 | Take a hit, use a buff or a stat stone, then type `wor.CompareAttributes` | Still 0 differ | [ ] |
| 3 | Type `wor.DumpAttributes` | Each combatant's attributes; Health and Energy match the HUD | [ ] |
| 4 | Play a full fight as usual | Nothing behaves differently; no new warnings in the Output Log about AttributeSync | [ ] |
