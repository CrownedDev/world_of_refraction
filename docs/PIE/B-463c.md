# PIE — B-463c: journal details (NEW, where found, lore kind, quest reward)

**Branch:** `feature/B-463c-journal-details` (in dev, built 2026-11-14).
**Already proven by tests:** `WoR.UI.Journal` (two new cases): a new memory or lore entry shows NEW until opened, and the save keeps which are new; a memory shows where it was found; a lore entry shows its kind and place, with a sub-tab per place; an older save shows nothing NEW and no place; a finished quest names its reward, an unfinished one keeps "Reward: shown when the quest is done."
**What changed:** Memories and Lore rows show **NEW** until you light them once (it goes when you move off). A memory's row reads where it was found ("Ember Trial, Present"; "Void Realm" in the hub), and the reader reads "{who} · found in {place}". A lore row reads its kind (Inscription, Note, Overheard, Item description), the reader "{kind} · {place}", and Lore has sub-tabs: Everything, then each place you read something in. A finished quest's reader ends "Reward: {what it gave}." Lore objects have a new **Kind** field in their Details panel (Inscription by default).
**Not checked by me (needs your eyes):** the look of the NEW tag next to a long title; a co-op friend's memory place (it is the place on their machine).
**Left out:** the memory replay window (waits for memory scenes); "found by {friend}" on lore; titles in the reward line (titles don't exist yet).

**Setup:** pull `dev`, build, start a run in a trial with a memory fragment and a lore object on its map. Saves made before this build show nothing NEW and no place for what they already had (expected).
