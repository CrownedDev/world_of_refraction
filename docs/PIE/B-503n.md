# PIE — B-503n: a test loadout for the v2 slots

**Branch:** `feature/B-503n-test-loadout-cloud` (cloud writer 7, 2026-11-15). **Unbuilt**: build it first.
**Already proven by tests:** `WoR.Debug.TestLoadout` (4 cases: the variant names, the crystals' elements, the evolution, no pawn refused). Nothing here runs the command on a real character.
**Setup:** build, open `TestLevel_Trial_01` (or any trial map), press Play. Open the console (`~`) for each command. The gear given is owned for good: it reaches the pool and the save, like any gear found in PIE.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | `wor.Debug.TestLoadout` | The Output Log's `[TestLoadout]` line names the played character and lists each piece: `in` or `refused (why), kept in storage`. A Generic: the Arming Sword (a crystal) in hand, the Longsword with the evolution, the Generic ring with a crystal; the Battle Axe and the second ring refused (two weapons and one adapter, D-210) | [ ] |
| 2 | Hold RB (R on keyboard) to open the wheel (B-503m4 / B-503m5) | One slice per loadout entry: the Arming Sword, the Longsword (the evolution), the Generic ring; each weapon's element options are its plain swing and its crystal or evolution | [ ] |
| 3 | `wor.Debug.TestLoadout` again | Nothing new is given (no duplicate popup); the same loadout, the same lines | [ ] |
| 4 | Open the loadout screen | The pieces from check 1 are in the entries, each socket showing its crystal or evolution | [ ] |
| 5 | `wor.Debug.TestLoadout Refractor` | Plays as `DA_Character_FireLord`: the Generic ring with a crystal as the first entry (a Refractor's adapter); the wheel shows the ring's slice and the innate Fire (no weapon line) | [ ] |
| 6 | `wor.Debug.TestLoadout Resonator` | Plays as `DA_Character_ResonatorLord`: the Arming Sword, then two adapters (one with a crystal, one with the evolution); the wheel has a slice for each | [ ] |
| 7 | `wor.Debug.TestLoadout BrokenDarkness`, then open the wheel | Plays as `DA_Character_BrokenDarknessLord` (a Broken Darkness character); the Darkness slice's options include Dark + the ring's element (B-503l / B-503m4) | [ ] |
| 8 | `wor.Debug.TestLoadout Reality`, then open the wheel | Plays as `DA_Character_RealityLord`; the Reality slice's options include (R) + the ring's element (B-503l / B-503m4) | [ ] |
| 9 | `wor.Debug.PrintTestLoadout` | The last report again | [ ] |
| 10 | After a variant, travel to the hub or another map | The pawn is the party leader again (the variant was the pawn only) | [ ] |

**Known limits:** a Refractor's single first entry holds the adapter, so its evolution has no place and is listed `refused` (D-210's own place for the evolution is a TODO in `LoadoutV2Model.cpp`). The command replaces the active loadout's gear (your old gear stays owned: put it back on the loadout screen). A variant swaps only the pawn's character data: its looks, its HP and the party card may still show the leader; if the strip doesn't follow within a second (the HUD's refresh), note it here.
