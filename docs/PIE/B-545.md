# PIE — B-545: no mouse-look errors on the title (from Crown's PIE)

**Branch:** `fix/B-545-frontend-look-input` (in dev, built and tested on the desktop 2026-11-16).

**What was wrong:** the menu level has no pawn, but it uses the hub's controller Blueprint for its UI root. Moving the mouse ran the Blueprint's look events, which call Get Pawn, so each move logged Accessed None (AddControllerPitchInput, AddControllerYawInput).

**Now:** the hub controller listens to its own input only while it has a pawn. On the title there is none, so the look events never run. The same holds in the moment between levels (going to a trial and back) before the new pawn arrives. Menus are not affected: they read the keys themselves. No editor step: the menu level keeps BP_HubPlayerController.

**Not tested by a spec:** a headless test can't make this controller (its widgets need a real player), so this sheet is the check.
