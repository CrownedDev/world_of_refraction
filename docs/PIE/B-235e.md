# PIE — B-235e: a client's own memory finds are theirs

**Branch:** `feature/B-235e-own-memory-finds-cloud` (cloud pre-write, built and specs green on the desktop 2026-11-08; in `dev`).
**Already proven by tests (once built):** `WoR.Memory.Sources`: a PriorMemory condition read on a friend's memories and on the team's together; standalone, a worn item's memory is the host's find.
**Setup:** 2-player PIE (Play As Listen Server, 2 players) in a trial run; the host plays **H**, the client **C**. A memory spot with a memory listing C (**M-Spot**), a fragment with a memory listing no character (**M-Frag**), a weapon C wears with a bound memory listing C (**M-Gear**, no trigger), and a memory **M-After** listing C with a PriorMemory condition on M-Spot.

**Known:** a client's `ServerReportJournal` is sent from `ClientInitialize`; if the PlayerState's owner has not reached the client by then, the report is dropped (check 1 shows it). A spot or fragment run on a client records into that client's run copy, not the host's run.
