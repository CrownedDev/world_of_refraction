# PIE — B-428: host hand-over chest records, and a leaver's dropped Prisms

**Branch:** `fix/B-428-handover-rekey` (in dev, built 2026-11-14; written by the cloud, built and tested on the desktop).
**Already proven by tests:** `WoR.Coop.HostSuccession`: after a hand-over the old host's opened chests stay the old host's, the new host's own become plain host records, shared records (fragments, spots, lore) and other players' chests are untouched. `WoR.Trial.Defeat`: a leaver's dropped Prisms are split equally among the players still there, the leftover to the host, and the drop is removed.
**What changed:** (a) on a host hand-over, opened-chest records follow the right player: no duplicate chest loot, and the new host isn't blocked from its own chests. (b) A friend who leaves a run mid-way has their dropped Prisms shared out among the players still there (Q-428 = A).
**Setup:** 3 players for (a); 2 or 3 for (b). A trial run with chests.

**Known gaps (follow-ups):** the **old host's own** drop isn't split when it hands hosting over (at that point the other players' wallets don't exist yet). A record counts as a chest's when its Blueprint's name contains "Chest", so a chest Blueprint must keep "Chest" in its name. If a player's online id is empty (LAN / no online service), the chest re-key in 1 does nothing: say if check 1's log line doesn't appear.
