# PIE — B-177: a crystal merge gives back its overshoot (ER-28)

**Branch:** `feature/B-177-merge-overshoot` (in `dev`).
**Already proven:**
- The editor builds and every test passes, including the new `WoR.Economy.CrystalMerge` spec.
- The spec checks that:
  - the change is the fewest crystals below the target (up to S)
  - an exact merge (2 D for a C) is unchanged
  - E + D + D for a C gives back one E
  - 3 F + 2 D for a C gives back one E and one F
  - a merge whose change does not fit is refused and fully refunded (**Q-177**)

**What changed (ER-28):** merging used to lose any value above the target. Now it comes back as the fewest lower crystals of the same type.

**Setup:**
- Open the editor on `dev` and start PIE in a level where your character has crystals and Prisms (the hub).
- Open the Output Log and the console (`~`).
- There is no merge screen yet, so use the debug command `wor.Economy.Merge <Type> <Tier>`. `wor.PrintEconomy` shows your wallet.

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Own exactly 2 D Garnets and nothing lower, then run `wor.Economy.Merge Garnet C` | Output Log: "Merged 2xD -> 1x ... (+0 change crystal(s), 0 value back)"; you now have one C Garnet and no D | [ ] |
| 2 | Own 1 E and 2 D Garnets, run `wor.Economy.Merge Garnet C` | Output Log: "Merged 1xE + 2xD -> 1x ... (+1 change crystal(s), 2 value back)"; you have one C and one E Garnet | [ ] |
| 3 | Run `wor.Economy.Merge Garnet C` with too few Garnets | A warning that the value is insufficient; nothing changes | [ ] |
| 4 | Run `wor.Economy.Merge Nope C` | The usage line: `wor.Economy.Merge <Type> <Tier>` | [ ] |
