# PIE — B-177: a crystal merge gives back its overshoot (ER-28)

**Branch:** `feature/B-177-merge-overshoot` (in `dev`).
**Already proven:**
- The editor builds and every test passes, including the new `WoR.Economy.CrystalMerge` spec.
- The spec checks that:
  - the change is the fewest crystals below the target (up to S)
  - an exact merge (2 D for a C) is unchanged
  - E + D + D for a C gives back one E
  - 3 F + 2 D for a C gives back one E and one F
  - a merge whose change does not fit is refused and fully refunded (**Q-177**) (hard to set up in PIE, so the spec covers it)

**What changed (ER-28):** merging used to lose any value above the target. Now it comes back as the fewest lower crystals of the same type.

**Setup:**
- Open the editor on `dev` and start PIE in a level where your character has crystals and Prisms (the hub).
- Open the Output Log and the console (`~`).
- There is no merge screen yet, so use the debug commands: `wor.Economy.GiveCrystal <Type> <Tier> [Count]` to get crystals, `wor.Economy.Merge <Type> <Tier>` to merge, `wor.PrintInventory` to see what you hold, `wor.PrintEconomy` for your Prisms (a merge costs Prisms).
- Before each check, make sure you hold no Garnets below C (check with `wor.PrintInventory`).
