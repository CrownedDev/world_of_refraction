# PIE — B-540: a piece that takes only one crystal type (D-231 point 5)

**Branch:** `feature/B-540-crystal-requirement` (in dev, built and tested on the desktop 2026-11-16).

**What it is (Crown):**
1. A weapon or adapter can be set to accept **only one crystal type** ("only an Emerald"). When its crystal is taken out or destroyed, only that type goes back in.
2. It is a setting on the weapon or adapter asset: **Accepted Crystal Type** (under Attached Item). Empty (None) takes any crystal, as before. A prebuilt uses its weapon or adapter asset, so setting it there covers the prebuilt too.
3. In the Equipment screen's add window, a crystal that doesn't fit stays in the list, **greyed**, saying "This piece takes only {type}."
4. Stones and evolutions are not limited (the setting names a gem).
5. The editor's data check flags a setting that names a stone, or an asset whose own crystal is another type.

**Already proven by tests:** `WoR.UI.LoadoutScreen` (fits; refused with the reason; unset takes any; a stone is not limited), `WoR.Inventory.GearAttach` (a refused gem debits nothing; its own type goes in).

## Editor step (do first)

| # | Do this |
|---|---|
| E1 | Pick one adapter or weapon the hub's starting gear uses (or a vendor sells). In its asset, under **Attached Item**, set **Accepted Crystal Type** to a gem you carry (for example Emerald). Save. Note which asset, so you can put it back after the check if it should not keep the rule: None is hidden in the dropdown, so use the field's reset arrow (back to None, any crystal) |
