# PIE — B-425: a co-op guest's saved wallet is no longer wiped

**Branch:** `fix/B-425-guest-wallet` (in dev, built 2026-11-14; written by the cloud, built and tested on the desktop).
**Already proven by tests:** `WoR.Economy.PlayerWallet`: a reported wallet (balances and carried run Gold) is applied on the host once; a second report after spending changes nothing. The join itself (the guest sending its save, and never saving the host's copy over its own) only shows with two players.
**What changed:** a guest sends its saved balances and run Gold to the host once when it joins. A guest never writes the host's copy of its wallet into its own save, at leave or at a save.
**Setup:** 2 players. Before joining, note the guest's balances in its own solo game (Prisms, essences, hub Gold).

| # | Do this | You should see | Result |
|---|---|---|---|
| 1 | Guest joins the host | The guest's wallet shows the balances from its own save, on both screens. Host's Output Log: `[Wallet] <guest>'s saved wallet applied on the host` | [ ] |
| 2 | Travel to another level together (start a run, or return to the hub) | The guest's balances are unchanged by the travel: nothing refilled, nothing lost | [ ] |
| 3 | Guest leaves, then plays solo | Its balances are what its save had **before** joining: not 0, not the host's numbers | [ ] |
| 4 | Guest rejoins | Same as 1 | [ ] |
| 5 | Host saves while the guest is in (rest spot or autosave) | Host's own balances are saved as before | [ ] |

**Known gap (follow-up row needed):** what a guest earns or spends **in co-op** is not written back to the guest's own save yet: after leaving, the guest has its pre-join balances. The first report is trusted (friends-only co-op; no cheat check until matchmaking).
