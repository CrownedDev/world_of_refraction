# PIE — B-582c: WASD moves through the battle menu (D-269)

**Branch:** `feature/B-582c-menu-nav`.
**What changed:** in the new battle HUD:
- W / S move a highlight up and down the open list (main menu, skill kinds, a skill list, items, the target rows, the Position picker), wrapping at the ends. On target rows it moves the target marker and camera, as hover does.
- D presses the highlighted row, as its number key or a click; on a target row it attacks / uses the skill, as Enter / Space.
- A goes back one step, as Backspace; nothing on the main menu.
- Q / E: nothing bound (the new HUD has no tab row yet).
- The fighter never moves on move input in a fight (`ACombatPlayerController::IsMoveInputIgnored` is always true).

**Already proven by tests:**
- `WoR.UI.CommandMenu.Keys`, the B-582c case: the main menu opens lit on Attack; W wraps to the last row, S wraps back and skips greyed Items; Back on the main menu does nothing; D opens the Attack picker lit on the foe; Back re-lights Attack; Skills, Abilities, then Back twice re-lights Abilities, then Skills; after both fighters Defend, the hero's new turn opens on Attack; D, D picks the target. The key list has W / S / D and A as Back, and no menu key on Q / E.
- `WoR.UI.CommandMenu.Keys`, the fight-move case: a possessed fighter gets no pending movement from move input.

- `WoR.UI.CommandMenu.Keys`, the D-270 cases: two foes, no name rows (tagged `field`), W / S cycle with wrap, the Position key does nothing in a pick, the pointer over a foe marks it, a left click picks it and a right click doesn't, D confirms the marked foe; the selector and Act tag follow the acting fighter's colour.
- `WoR.UI.CommandMenu.Keys`, the trace case (QA fix): the fight controller's live pointer trace is the Pawn channel, which a fighter's capsule blocks. `WoR.UI.BattleHUD`: a foe with no effects has no status row on its card. The box pick: the nearest fighter whose screen box holds the pointer, none outside, an unbuilt box never.

**Not proven there:** the highlight's look, real key presses, the camera following, a Blueprint that might walk the fighter some other way, a pad, a real pointer hit on a fighter's body, the floating-card click.

**Written for an agent with `WoRAgentPlayToolset`** (`Conventions/HandsOffPlan.md`). Play on the QA save folder only, at `SetWindowSize(Width=1280, Height=720)`.
