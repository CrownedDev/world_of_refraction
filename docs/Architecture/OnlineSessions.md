# Online sessions

## Overview
B-233 (D-103, Q-233): co-op players host, find and join a session through Unreal's online subsystem. The code is written against the generic session interface (`IOnlineSession`), so the platform is a config choice: the **Null** subsystem (LAN) now, EOS (with Steam friends on top) once Crown's EOS ids exist.

## Architecture
- `UWoRSessionSubsystem` (game instance, `Online/WoRSessionSubsystem.h`): `HostSession` (create, then `ServerTravel` the current level `?listen`), `FindSessions` (LAN query on Null, lobbies otherwise), `JoinFoundSession` (join, then `ClientTravel` to the resolved address), `LeaveSession`, `GetSessionString`.
- `WoRSession::MakeHostSettings`: 3 public connections (D-150), advertised, join in progress, invites; LAN on Null, presence and lobbies otherwise.
- Config: `.uproject` enables OnlineSubsystem / OnlineSubsystemNull / OnlineSubsystemUtils; `DefaultEngine.ini` `[OnlineSubsystem] DefaultPlatformService=Null`.
- B-233b invites: `ReadFriends` (the platform's default friends list; none on Null), `GetFriendNames`, `InviteFriend` (to the hosted session), `IsHosting`; the platform's invite-accepted event is bound once a session interface exists (`EnsureInviteBinding`) and joins through `JoinResult` (shared with `JoinFoundSession`).
- B-233b drop-in and leaving (`Player/RunStateComponent.h`, Q-233b): `RunJoinRules::CanSeatJoiner` (outside a run always; in a run only at a rest spot, `UTrialRunSubsystem::IsAtRestSpot`; a friend taking back its own held seat always); `AcceptJoin` checks it. A remote player's logout (`FGameModeEvents::GameModeLogoutEvent`; seamless travel fires none) calls `HandlePlayerLeft`: its request goes, its claims are released, its members become AI seats held for its unique net id (`GetHeldFor`); in a fight they wait for `OnCombatEnded` (applied the next tick, as `EndCombat` broadcasts before the fight ends).
- Placeholder UI: `UInviteWidget` (`wor.UI.Invite`; the rest menu's "Invite and seat friends", host only): session state, friends with Previous / Next / Invite, Host, Seat a friend (`UJoinSeatWidget`, which now says when seating waits for a rest spot and marks held seats).

## Integration Points
- After the travel, the D-150 join flow (`URunStateComponent::RequestJoin` / `AcceptJoin`) seats the joiner.
- Debug: `wor.Session.Host`, `wor.Session.Find`, `wor.Session.Join <index>`, `wor.Session.Print`, `wor.Session.Friends`, `wor.Session.Invite <index>`; `wor.Run.PrintState` shows the rest-spot gate, held seats and seats waiting for a fight's end.

## Known Limitations / TODOs
- EOS config and Steam on top: B-233c (needs Crown's EOS ids, Q-233).
- B-233b: held seats are per level (a level change forgets the hold; the seat stays AI). A friend coming back with a different character on its held seat swaps it like any AI seat. The rest-spot gate reads the host's run (`IsAtRestSpot`), which any player's rest sets. No invite on LAN (no friends list). A logout while the world closes or during a host hand-over (B-234c) changes no seat. A player with no unique net id leaves a plain AI seat (no hold). No headless spec for the mid-fight drop (PIE check).
- Host hand-over: B-234b (a lost host), B-234c (planned, at a rest spot), B-234d (the new host's own party and pool after the run; the join order across a travel). A new host that hands over again in the middle of the copied run stays on the copy until a restart (Q-234d).
